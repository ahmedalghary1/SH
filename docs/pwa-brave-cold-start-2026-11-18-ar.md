# فتح PWA دون إنترنت في Brave على ويندوز — 18 نوفمبر 2026

فُحصت الملفات العامة على `https://sh.elwsamstore.com/`. كانت ملفات Service Worker وإدارة التثبيت والمزامنة مطابقة للنسخة المحلية قبل هذا الإصلاح، وجميع الملفات الأساسية الـ33 متاحة باستجابة 200 وبنوع محتوى مناسب. صفحة البداية تحوّل المستخدم غير المسجل إلى صفحة الدخول. لم يستخدم الفحص بيانات دخول أو بيانات متصفح المستخدم.

## العيوب التي عولجت

- تسجيل Service Worker كان مستثنى من صفحة الدخول، رغم إمكان تثبيت الموقع من واجهة المتصفح في هذه الصفحة. كان يمكن إنشاء تطبيق مثبت بلا عامل جاهز للتشغيل دون اتصال.
- التسجيل كان ينتظر حدث `window.load`؛ صورة بطيئة أو طلب تحميل عالق يؤخر تجهيز الأوفلاين. التسجيل يبدأ الآن مباشرة عند تحميل ملف التطبيق.
- تجهيز HTML كان يتوقف حتى اكتمال أول bootstrap وحفظ قائمة الصفحات المسموحة. الصفحة الأولى بعد تسجيل الدخول تكون قد حُمّلت قبل أن يتحكم العامل فيها، فلا تُحفظ تلقائيًا. يُحفظ الآن عنوان البداية `/` والصفحة الحالية بصورة مستقلة عن تنزيل بيانات الحساب، ثم تُجهَّز بقية الصفحات المصرح بها.
- اكتمال bootstrap أثناء تجهيز الواجهة الأولية لم يكن يضمن إعداد الصفحات الجديدة قبل إعلان الجاهزية. تُراجع قائمة الصفحات الأحدث ويكتمل تجهيزها قبل تفعيل جاهزية الأوفلاين وزر التثبيت الداخلي.
- اختلاف معلمات عنوان البداية مثل `/?source=installed` كان يمنع استخدام النسخة المحفوظة من `/`. يُستخدم الآن المستند المحفوظ للحساب والنطاق الصحيحين.
- فشل Cache Storage كان يمكن أن يرفض استجابة التنقل بالكامل. أصبح هناك بديل HTML مستقل عن التخزين وملفات CSS، كما لم تعد استجابة بوابة 502/503/504 فارغة تُمرَّر كشاشة فارغة إذا لم توجد صفحة محلية.
- عندما يعلن النظام انقطاع الشبكة فعلًا، تُفتح الواجهة المحفوظة مباشرة بدل انتظار مهلة طلب الشبكة في نافذة التشغيل الفارغة.

تثبيت التطبيق من قائمة Brave يظل قرارًا للمتصفح، لذلك تعرض الواجهة بعد التثبيت رسالة تطلب إبقاء الإنترنت حتى اكتمال تجهيز البيانات إذا لم تكن جاهزة. زر SH الداخلي لا يبدأ نافذة التثبيت قبل تأكيد الجاهزية. لا يعني ظهور أيقونة التطبيق وحده اكتمال حفظ بيانات العمل.

## التحقق

استخدمت الاختبارات نسخة Brave المثبتة على ويندوز، مع ملفات مستخدم وقواعد بيانات مؤقتة مستقلة عن التشغيل:

- أول فتح قبل تسجيل الدخول يعطي صفحة أوفلاين مفهومة بدل صفحة فارغة.
- الصفحة الحالية وعنوان البداية محفوظان رغم تعطل أول تنزيل للبيانات، ودون اشتراط إعادة تحميل الصفحة.
- مورد صورة عالق لا يؤخر تجهيز العامل وصفحة البداية.
- فتح عنوان البداية بمعلمات إضافية أثناء تعطل السيرفر يستخدم الواجهة المحلية المعزولة للحساب.
- عودة الاتصال تكمل البيانات والصفحات قبل إعلان الجاهزية.
- إغلاق Brave بالكامل وإعادة تشغيله أثناء تعطل السيرفر يحافظ على الواجهة وطابور المزامنة ومفتاح إعادة المحاولة.
- اختبار الأعمال في Brave نجح للفواتير والقبض والتحويلات والمخزون وفقد رد السيرفر وإعادة المحاولة وانتهاء الجلسة وإعادة الدخول.
- نجاح 66 اختبار JavaScript، وتشغيل 21 اختبار Django للمزامنة وبيانات PWA دون فشل، مع تخطي اختبار تزامن واحد يحتاج PostgreSQL.

لا يثبت الاختبار قراءة إعدادات ملف Brave الشخصي المتأثر؛ إذا كانت سياسات المتصفح تمنع التخزين أو JavaScript، فستظل بحاجة إلى السماح بهما للموقع. لم يُغيّر الإصلاح إعدادات Brave أو يحذف أي قاعدة محلية أو عمليات معلقة.

## التفعيل على الموقع

1. نشر ملفات JavaScript والقالب المحدث وملف العامل معًا.
2. تشغيل `python manage.py collectstatic --noinput` وإعادة تشغيل التطبيق. لا توجد migration جديدة.
3. فتح الموقع نفسه في Brave مع الإنترنت وتسجيل الدخول. حفظ العمل ومزامنة العمليات المعلقة ثم قبول «تحديث التطبيق»، أو إغلاق نوافذ التطبيق والموقع كلها وإعادة فتحه مع الاتصال لتفعيل العامل المنتظر.
4. انتظار ظهور «جاهز للعمل دون اتصال» قبل قطع الإنترنت، ثم إغلاق التطبيق وإعادة فتحه دون اتصال للتحقق من عنوان البداية.

إصدار العامل بعد تصحيح «كل المعارض» هو `sh-pwa-v2026-11-18-scope-ready-03`. النسخة المثبتة القديمة تحتاج تنزيل هذا الإصدار؛ لا تُصلَح ملفاتها بمجرد تعديل المشروع على جهاز التطوير. لا تمسح بيانات الموقع أو تُزل التطبيق مع بياناته لمعالجة المشكلة.

## تصحيح رسالة التجهيز الدائمة في «كل المعارض»

كان قالب `base.html` يرجع إلى معرض ملف المستخدم عندما يكون اختيار المسؤول «كل المعارض». مثلًا، يرسل المتصفح نطاق `u7-b3-rmanager-s1` بينما النطاق الفعلي في السيرفر هو `u7-ball-rmanager-s1`. يرفض السيرفر الطلبات المختلفة بـ409، فلا يُنزَّل bootstrap ولا تكتمل الجاهزية، ويظل زر التثبيت معطلًا.

أصبح القالب يستخدم المعرض النشط وحده للمسؤول الأعلى، ويضم نطاق `request.pwa_scope` الذي حسبه السيرفر. تستخدم الهوية المحلية هذا النطاق بعد مطابقته مع المستخدم والدور وصلاحية المسؤول. وعند فتح صفحة قديمة محفوظة دون اتصال، يضيف العامل نطاقها الموثق من رأس الاستجابة إلى HTML، لتجنب تكرار تفسير معرض الملف الشخصي خطأ.

توضح الحالة الآن إن كان السبب بيانات لم تكتمل، أو اختلاف نطاق المعرض، أو ملفات وصفحات مفقودة، أو فشل العامل، ويعرض التلميح تفاصيل التعثر. يمكن فحص الحالة كذلك من `SHSync.getOfflineReadiness()`. لا تُلغى شروط الجاهزية ولا يُفعّل التثبيت قبل اكتمال التجهيز الحقيقي.

تأكد الاختبار من تطابق HTML ورأس الاستجابة وجلسة المزامنة عند اختيار كل المعارض أو معرض آخر مختلف عن معرض ملف المسؤول، ومن إمكانية قراءة صفحات الأوفلاين لأدوار المندوب والمخزن والمدير والمسؤول الأعلى. نجح اختبار Brave الفعلي لحساب مسؤول مرتبط بمعرض مع اختيار كل المعارض، ووصل إلى الجاهزية وتفعيل زر التثبيت. ونجح 71 اختبار JavaScript و32 اختبار Django دون فشل، مع تجاوز اختبار PostgreSQL واحد.

يلزم نشر **`templates/base.html` مع ملفات PWA**، ثم جمع الملفات الثابتة وإعادة تشغيل التطبيق وتحديث النسخة المثبتة. لم يتغير مخطط IndexedDB ولم تُحذف قواعد النطاقات القديمة أو عملياتها، ولم تُنقل تلقائيًا عمليات معرض إلى نطاق كل المعارض.
