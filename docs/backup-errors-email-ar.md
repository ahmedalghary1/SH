# تشخيص فشل النسخ الاحتياطي وتنبيهات البريد

## ما ثبت بالفحص

كان فشل التنزيل من نوع `BackupError` يعاد إلى الصفحة دون تسجيل استثناء أو إرسال تنبيه. وكانت بعض الاستثناءات الأخرى غير معالجة في شاشة النسخ. واعتمد عرض الخطأ على رسالة مؤقتة يمكن أن تستهلكها طلبات الصفحات الخلفية، فلا تبقى للمستخدم رسالة واضحة. كذلك لم يكن مسجل الأخطاء العام يكتب أخطاء وحدات النسخ إلى `errors.log`.

كان إرسال الأخطاء يستخدم معالج Django الافتراضي الذي يستدعي الإرسال مع `fail_silently=True`، فلا يظهر للمستخدم رفض SMTP أو فشل الاتصال. ولم يكن المعالج يضاف أصلًا إذا غابت كلمة مرور البريد، دون توضيح نقص الإعدادات على الشاشة. ملف `.env.example` توثيق فقط؛ يقرأ التطبيق ملف `.env` الخاص ومتغيرات عملية الاستضافة.

وجد أيضًا خطأ مستقل في تجهيز الأرشيف: فحص الصور المفقودة كان يعامل أي قيمة JSON تتضمن `path` كأنها حقل صورة، ثم يطلب منها `sha256`. يؤدي ذلك إلى `KeyError` عند وجود بيانات JSON عادية بهذه الصيغة، مثل سجل مراجعة. أصبح الفحص مقتصرًا على حقول الملفات والصور الفعلية. أضيف كذلك فحص عدد السجلات قبل إنشاء تعريفاتها وتحميلها للنسخ لتجنب تجاوز الحد بعد استهلاك الذاكرة بالفعل.

أصبح فحص مجلدات المرفقات يرفع خطأ صلاحية القراءة بدل تخطي مجلد غير قابل للقراءة بصمت، حتى لا تعلن الأداة نجاح نسخة ناقصة المرفقات.

**هذه أسباب مثبتة في الكود، وليست إثباتًا للاستثناء الذي حدث على الموقع المنشور.** سجل الاستضافة غير متاح للفحص حاليًا. نجح إنشاء الأرشيف محليًا، لكن لا يثبت ذلك حالة ترحيلات الاستضافة أو صلاحيات ملفاتها أو مواردها أو اتصال بريدها. وفي البيئة المحلية كانت كلمة مرور SMTP غير مضبوطة؛ لا يمكن الجزم بأن إعداد الموقع المنشور مطابق لها.

## السلوك بعد الإصلاح

- عند فشل التجهيز تظهر رسالة ثابتة داخل الصفحة، مع رقم متابعة في النص وفي رأس `X-Request-ID`، دون تحويل HTML إلى ملف ZIP. تعرض رسائل مفهومة لنقص المساحة، وصلاحيات الملفات، والترحيلات الناقصة، وأخطاء قاعدة البيانات والأخطاء غير المتوقعة.
- يسجل الاستثناء الأصلي وتتبع الاستدعاء بالرقم نفسه. وعندما تتعطل معالجات قالب الواجهة بسبب قاعدة البيانات، تستخدم صفحة خطأ مستقلة لا تعتمد على معالجات السياق المتصلة بالقاعدة.
- تحاول أخطاء الخادم والتجهيز إرسال التنبيه إذا فعّلته البيئة. لا يرسل إدخال ZIP غير صالح أو تعارض دمج متوقع تنبيهًا بوصفه خطأ خادم.
- يحتوي التنبيه رقم المتابعة ونوع العملية والمسار دون معاملات الرابط وتتبع الاستثناء. لا يتضمن جسم الطلب أو ملفات المستخدم المرفوعة أو الكوكيز أو المتغيرات المحلية أو قائمة إعدادات Django. تحجب الأسرار المضبوطة وكلمات المرور والرموز المعروفة في النص والسجل.
- يكتب نجاح تسليم التنبيه لمحرك البريد باسم `ERROR_EMAIL_SENT`. ويكتب نقص الإعدادات باسم `ERROR_EMAIL_NOT_READY`، وفشل الإرسال باسم `ERROR_EMAIL_SEND_FAILED` مع تصنيفه وكود SMTP إن وجد. تسجل هذه الأحداث عبر مسجل منفصل لا يرسل بريدًا، لتجنب تكرار تنبيهات فشل البريد نفسها.
- تعرض شاشة النسخ نقص إعدادات البريد، وتعرض سبب فشل الإرسال المكتشف في العملية الحالية. تحتفظ العملية أيضًا بآخر حالة في ذاكرتها؛ قد تختلف الحالة المعروضة بعد الانتقال إلى عامل استضافة آخر أو إعادة تشغيله. السجل هو المرجع الدائم عند تفعيل التسجيل للملفات، وإلا تستخدم سجلات تطبيق Python لدى الاستضافة.
- يمنع إرسال أكثر من تنبيه للطلب نفسه، ويقلل تكرار الحدث المتطابق لمدة خمس دقائق افتراضيًا. المنع محلي لكل عامل تشغيل ولا يعتمد على قاعدة البيانات أو خدمة التخزين المؤقت، حتى لا يعطل فشلهما تنبيه البريد.

## تطبيق الإصلاح على الموقع المنشور

انشر الملفات المحدثة، واحتفظ بملف `.env` الخاص وبيانات التشغيل، ثم شغل داخل بيئة Python الخاصة بالموقع:

```sh
python manage.py migrate
python manage.py check
python manage.py check_backups --create
python manage.py check_error_email
```

الأمر `check_backups --create` يبني ZIP مؤقتًا باستخدام المسار نفسه الذي يستخدمه زر التنزيل، ثم يتحقق من البيانات وبصمات جميع المرفقات ويحذف الملف المؤقت. لا يدمج بيانات ولا يعيد تسجيل الحركات أو تغيير الأرصدة. قد ينشئ أو يحدث تعريفات النسخ وتاريخ بصمات الفروع، كما يفعل التنزيل العادي. إذا فشل يطبع رسالة آمنة ورقم متابعة ويسجل الاستثناء. تشغيله دون `--create` يفحص الترحيلات وحدود النسخ والكتابة المؤقتة فقط.

راجع في ملف `.env` الخاص على الاستضافة أو إعدادات عملية التشغيل:

```dotenv
ERROR_EMAIL_ENABLED=True
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
EMAIL_HOST_USER=your-mailbox@example.com
EMAIL_HOST_PASSWORD=YOUR_PRIVATE_APP_PASSWORD
ERROR_EMAIL_TO=your-mailbox@example.com
EMAIL_TIMEOUT=10
ERROR_EMAIL_REPEAT_SECONDS=300
```

المضيف في المثال خاص بـGmail؛ استخدم إعدادات مزود بريدك الفعلية. لا تضع كلمة المرور الحقيقية في `.env.example` أو التقرير أو سجل الخطأ. عند استخدام `smtp.gmail.com` يزيل التطبيق مسافات كلمة مرور التطبيق المنسوخة. لا يزيل مسافات كلمات مرور مقدمي البريد الآخرين.

بعد تعديل الإعدادات أعد تشغيل تطبيق Python من لوحة الاستضافة، ثم افحص الاتصال والمصادقة دون إرسال رسالة:

```sh
python manage.py check_error_email --connect
```

ولإرسال رسالة اختبار واحدة إلى العناوين المضبوطة، عند الرغبة:

```sh
python manage.py check_error_email --send-test
```

الإرسال العادي والاختبار لا يثبتان وصول الرسالة لصندوق الوارد؛ قبول SMTP قد يتبعه تصنيف الرسالة كرسالة غير مرغوبة أو رفض لاحق. افحص صندوق الوارد والبريد غير المرغوب فيه. لا تطبع أوامر التشخيص كلمة المرور أو عنوان المرسل أو المستلمين.

أعد تجربة تنزيل النسخة من حساب المستخدم الأعلى على الموقع. عند الفشل ستظهر رسالة ورقم متابعة يمكن مشاركتهما دون إرسال ملف البيئة. إذا قطع خادم الويب العملية قبل أن تعود استجابة Python، مثل إنهاء العامل بسبب الذاكرة أو المهلة، فلا يستطيع كود التطبيق ضمان عرض رقم أو إرسال تنبيه؛ حينها يلزم فحص حدود الاستضافة وسجل الخادم.

## اختبارات الإصلاح

تغطي اختبارات النسخ حقل JSON العادي الذي يتضمن `path`، والتنزيل السليم والتحقق من الأرشيف، وحد السجلات المبكر، ورسالة الخطأ الثابتة ورقمها، وتعطل المساحة والصلاحيات وقاعدة البيانات، والصفحة الاحتياطية المستقلة، ونقص الترحيلات، وفشل SMTP مع بقاء خطأ النسخ ظاهرًا. وتغطي اختبارات البريد إخفاء الأسرار، ومنع التكرار، ورفض المصادقة، وعدم قبول الرسالة، ونقص كلمة المرور، وتعارض TLS/SSL، وأوامر التشخيص.

تستخدم اختبارات البريد محركًا داخل الذاكرة ومحاكاة SMTP؛ لا ترسل رسائل فعلية. وتستخدم اختبارات البيانات قواعد ووسائط منفصلة. يشغل فحص المتصفح Service Worker فعليًا، ويتأكد من استمرار تنزيل يستغرق أكثر من ثماني ثوانٍ، وظهور فشل التجهيز دون تنزيل HTML، ثم رفع الأرشيف ودمجه.

لتشغيل اختبارات الإصلاح:

```sh
python manage.py test config.tests_error_email settings_app.tests_backups config.tests.LogSanitizerTests
node --test tests/js/*.test.js
python tests/backups_browser_review.py
```

لا تعني هذه النتائج أن الملفات نشرت على الموقع الخارجي أو أن اتصال SMTP الخاص بالاستضافة اختبر. يلزم تنفيذ خطوات التفعيل والفحص أعلاه داخل بيئة الموقع.
