# نظام المعارض المتعددة

أصبح كل سجل تشغيلي تابعًا لمعرض (`Branch`) مع عزل تلقائي بحسب المستخدم المسجل دخوله.

## الصلاحيات

- المستخدم العادي ومدير المعرض يعملان داخل المعرض المسجل على حسابهما فقط.
- مدير المعرض يستطيع إنشاء مستخدمين داخل معرضه، ولا يستطيع نقلهم إلى معرض آخر.
- الـ Super Admin يستطيع إدارة المعارض وربط المستخدمين بها.
- يظهر للـ Super Admin محدد معرض أعلى جميع صفحات النظام. اختيار «كل المعارض» للعرض المجمع، واختيار معرض محدد للعمل داخله وإنشاء بيانات جديدة.
- الـ API يعزل البيانات حسب معرض صاحب الـ token. يمكن للـ Super Admin إرسال `X-Branch-ID` لاختيار معرض محدد.

## البيانات المعزولة

يشمل العزل: المنتجات والمتغيرات والتصنيفات والألوان والمقاسات، المخازن والأرصدة والدفعات والحركات، العملاء وتفاعلاتهم، الطلبات وبنودها والفواتير، الخزن والحركات المالية، الموردين والمشتريات، المرتجعات، عهد وتحصيلات المندوبين، إعدادات الشركة، المزامنة وسجل التدقيق.

يمكن تكرار SKU ورقم الفاتورة ورقم أمر الشراء في معرض آخر، لكن لا يمكن تكراره داخل المعرض نفسه.

## ترحيل النظام القائم

الترحيلات تنشئ تلقائيًا معرضًا باسم «المعرض الرئيسي» وكود `MAIN`، وتنقل إليه كل البيانات القديمة وكل المستخدمين غير الـ Super Admin. لا تُحذف أو تُكرر أي بيانات قديمة.

بعد أخذ نسخة احتياطية من قاعدة الإنتاج، نفّذ:

```bash
python manage.py migrate
```

بعد ذلك سجّل الدخول بحساب Super Admin، افتح «المعارض»، أضف المعرض الثاني، ثم عدّل كل مستخدم وحدد معرضه الصحيح. البيانات القديمة ستظل في المعرض الرئيسي ويمكن إدخال بيانات المعرض الثاني بصورة مستقلة.

## قواعد السلامة

تتحقق طبقة النماذج من تطابق المعرض بين العلاقات الحساسة؛ لذلك لا يمكن ربط منتج من معرض بمخزن أو فاتورة أو مرتجع تابع لمعرض آخر حتى عند إرسال المعرّفات يدويًا. ولا يعتمد العزل على إخفاء عناصر الواجهة فقط، بل يطبق على استعلامات ORM أثناء الطلب وعلى واجهة المزامنة أيضًا.
