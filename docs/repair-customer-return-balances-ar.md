# تصحيح رصيد عميل قديم على السيرفر

## من داخل الموقع

بعد نشر التحديث، سجّل الدخول بحساب مدير، وافتح ملف العميل ثم اضغط **مراجعة رصيد المرتجعات**. الرابط موجود في صفحة العميل المبسطة والكاملة.

تعرض الشاشة المتبقي المسجل والمتبقي بعد المطابقة لكل فاتورة. حدّد الفواتير التي تظهر **متاحة للتصحيح**، ثم فعّل تأكيد مراجعتها واضغط **تصحيح الفواتير المحددة**. تتحدث المراجعة وكشف العميل بعد التنفيذ. الحالات التي تحتاج مراجعة مستقلة تعرض السبب بالعربية ولا يمكن اختيارها.

تظل المراجعة صالحة لمدة نصف ساعة، وترتبط بالعميل والفرع والمستخدم الذي فتحها. إذا سُجلت دفعة أو تغيرت بيانات فاتورة بعد فتح الشاشة، يتوقف التصحيح وتُعرض مراجعة جديدة. إعادة إرسال الطلب لا تعيد تطبيق الفرق. يلزم الاتصال بالموقع لتنفيذ التصحيح، ولا يوضع ضمن قائمة المزامنة دون اتصال.

لا تحتاج تشغيل أوامر صيانة لكل عميل بعد نشر هذه الشاشة. التعليمات التالية متاحة كخيار بديل للمسؤول عن السيرفر.

الأمر `reconcile_customer_returns` مخصص لمراجعة الخطأ القديم الذي أعاد مديونية المرتجع عند تسجيل دفعة لاحقة. الوضع الافتراضي يعرض تقريرًا فقط. التنفيذ يصحح `remaining_amount` وحالة السداد للفواتير المحددة، ويسجل التغيير في سجل المراجعة. لا يحرّك المخزون أو الخزن، ولا يحذف دفعات أو مرتجعات، ولا يغير الرصيد الافتتاحي للعميل.

## 1. تجهيز الموقع

خذ نسخة احتياطية لقاعدة بيانات الموقع من لوحة الاستضافة. ارفع التحديث الحالي كاملًا، بما فيه `finance/reconciliation.py` و`finance/management/` وتعديل `returns/services.py`، ثم أعد تشغيل تطبيق الموقع.

افتح Terminal على الاستضافة، وفعّل بيئة Python الخاصة **بنفس الموقع** باستخدام أمر التفعيل الذي تعرضه إدارة تطبيق Python في الاستضافة. انتقل إلى مجلد المشروع الذي يحتوي `manage.py`. احتفظ بملف `.env` وإعدادات اتصال قاعدة البيانات الحالية؛ لا تختَر SQLite ولا تنسخ قاعدة البيانات المحلية إلى السيرفر.

```sh
python manage.py check
python manage.py migrate --plan
python manage.py migrate
```

يحتاج تحديث إلغاء المرتجع السابق إلى ترحيل `returns.0004`. لا يضيف أمر المطابقة نفسه ترحيلًا جديدًا.

## 2. إنشاء تقرير دون تعديل البيانات

استبدل `CUSTOMER_ID` برقم العميل الداخلي، مثل الرقم الذي يظهر في رابط `/customers/42/`. استخدم اسمًا جديدًا للتقرير في كل مراجعة؛ الأمر يرفض الكتابة فوق ملف موجود. المسار التالي داخل مجلد حساب الاستضافة الخاص، خارج مجلد الويب العام.

```sh
python manage.py reconcile_customer_returns --customer CUSTOMER_ID --output "$HOME/return-review.json"
```

ستظهر أعمدة: `Order` رقم الفاتورة الداخلي، و`stored` المتبقي المسجل، و`expected` المتبقي بعد المطابقة. هذا الرقم الداخلي يطابق رقم الفاتورة في رابط `/orders/87/`، وليس نص رقم الفاتورة المطبوع.

- `OK`: لا يوجد فرق يحتاج تصحيحًا.
- `REPAIR AVAILABLE`: الدفعات وقيم المرتجعات مترابطة ومتطابقة، ويوجد فرق يمكن تصحيحه.
- `BLOCKED`: توجد بيانات ناقصة أو غير متطابقة؛ لن يصلحها الأمر تلقائيًا.

تراجع الأداة المدفوع المسجل مقابل القبض ورد الدفعات، بعد استبعاد الحركات المرتبطة بالمرتجعات نفسها. وتراجع قيمة كل مرتجع مقابل أصنافه والجزء الذي خُصم من الدين والجزء النقدي. المتبقي المتوقع هو إجمالي الفاتورة ناقص المدفوع وناقص تخفيض الدين للمرتجعات المكتملة غير الملغاة.

من أسباب المنع: `paid_amount_does_not_match_receipts` يعني أن المدفوع لا يطابق الدفعات المتاحة؛ و`cash_links_mismatch` يعني أن حركات المرتجع النقدية غير متطابقة؛ و`paid_and_return_credit_exceed_invoice_total` يعني وجود تحصيل زائد يحتاج مراجعة منفصلة. لا تحوّل هذه الحالات إلى صفر أو تحذف حركات لمجرد إغلاق الفرق.

## 3. تصحيح الفواتير التي راجعتها فقط

بعد مراجعة الأرقام، استبدل `ORDER_ID` برقم الفاتورة الداخلي من التقرير، و`MANAGER_USERNAME` باسم دخول مدير نشط من نفس الفرع، أو مسؤول النظام. نفّذ ذلك أثناء توقف المستخدمين مؤقتًا عن تسجيل دفعات أو مرتجعات لهذا العميل.

```sh
python manage.py reconcile_customer_returns --customer CUSTOMER_ID --report "$HOME/return-review.json" --order ORDER_ID --actor MANAGER_USERNAME --apply
```

لتحديد أكثر من فاتورة، كرّر `--order` لكل رقم. لا يصلح الأمر أي فاتورة لم تحددها. إذا تغيرت الفاتورة أو الدفعات أو المرتجعات منذ إنشاء التقرير، يتوقف الأمر دون تنفيذ التصحيح ويطلب تقريرًا جديدًا. وإذا كانت إحدى الفواتير المحددة غير قابلة للتصحيح، تُلغى مجموعة التصحيحات كلها.

الأمر يعيد حساب القيمة من البيانات الحالية؛ تعديل قيمة `remaining_expected` يدويًا داخل التقرير لا يفرض مبلغًا على قاعدة البيانات. لا تستخدم التقرير القديم لإعادة التطبيق بعد التصحيح؛ أنشئ تقريرًا جديدًا للتحقق.

## 4. التحقق

افتح كشف العميل في الموقع ثم أنشئ تقريرًا جديدًا باسم مختلف:

```sh
python manage.py reconcile_customer_returns --customer CUSTOMER_ID --output "$HOME/return-review-after.json"
```

يجب أن تظهر الفواتير المصححة بحالة `OK`. المرتجع الفعلي يبقى في الكشف بوصفه حركة صحيحة؛ يزول الفرق القديم الناتج عن المتبقي الخاطئ. إذا كنت تريد إلغاء المرتجع نفسه لاحقًا، استخدم زر الإلغاء بعد المطابقة. أُضيف فحص يمنع تعديل المرتجع أو إلغاءه إذا كان المتبقي غير متطابق، حتى لا يتراكم الخطأ القديم مع أثر الإلغاء.
