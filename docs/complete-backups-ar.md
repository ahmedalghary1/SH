# النسخ الاحتياطي الكامل ودمج البيانات

تاريخ الإضافة: 16 نوفمبر 2026.

## الوصول والاستخدام

من **الإعدادات ← النسخ الاحتياطي**. الميزة مخصصة للحساب الأعلى `superuser` لأنها تشمل جميع المعارض والمستخدمين، حتى إذا كان الحساب يعرض فرعًا محددًا حاليًا. لا تمنح أدوار المندوب أو المخزن أو مدير الفرع وصولًا لنسخة معارض أخرى.

1. اختر **تنزيل البيانات والصور** للحصول على ملف ZIP واحد.
2. عند الحاجة إلى الدمج، ارفع الملف نفسه من **رفع ومعاينة الدمج**.
3. راجع السجلات الجديدة والتحديثات والموجودة والتعارضات وعدد الصور.
4. إذا لم توجد تعارضات، فعّل مربع المراجعة واضغط **تأكيد دمج البيانات والصور**.

رفع الملف لا ينفذ الدمج مباشرة. تبقى المعاينة صالحة لمدة ساعة. إذا تغيرت البيانات أو الصور بعد المعاينة، يطلب النظام رفع النسخة مجددًا قبل التطبيق.

## ما تتضمنه النسخة

- جميع المعارض والمستخدمين وبيانات حساباتهم المحفوظة ومجموعاتهم وصلاحياتهم.
- المنتجات والتصنيفات والألوان والمقاسات والأسعار.
- العملاء والموردين والمتابعات.
- المخازن والأرصدة والدفعات والحركات.
- المبيعات وبنودها والفواتير ولقطات بياناتها التاريخية.
- المشتريات وبنودها ومدفوعاتها.
- الخزن والحركات المالية والقبض والصرف والتسويات.
- المرتجعات والاستبدال وروابط التسويات والمدفوعات.
- عهد المندوبين وتحصيلاتهم، وسجلات المراجعة والمزامنة ومنع التكرار.
- إعدادات الشركة، وجميع الملفات الموجودة في مجلدات المرفقات المعتمدة ومجلداتها الاحتياطية، بما يشمل صور المنتجات والشعار المرفوع والملفات غير المرتبطة بسجل حالي.

إذا احتوت قاعدة البيانات رابط صورة لا يوجد ملفها أصلًا، تسجل النسخة هذا النقص ويظهر عدده في المعاينة. لا يمكن استعادة ملف لم يكن موجودًا في المصدر.

هذه نسخة **بيانات ومرفقات الخادم**؛ لا تشمل كود التطبيق أو ملف البيئة الخاص أو كلمات الاتصال بالخادم أو جلسات تسجيل الدخول. صور الواجهة الثابتة الموزعة مع كود البرنامج ليست ملفات رفع للمستخدمين. وتلزم مزامنة أجهزة المندوبين أولًا لتضمين عملياتهم التي لا تزال محفوظة على أجهزتهم فقط.

النسخة تضم بيانات تجارية وشخصية وبيانات حسابات محفوظة، وهي ZIP غير مشفر؛ تحفظ في مكان خاص. أدوات تشفير نسخ قاعدة البيانات القديمة تظل مسارًا منفصلًا.

## قواعد الدمج

### منع التكرار وإعادة ربط السجلات

يحفظ النظام معرفات ثابتة للسجلات، مستقلة عن أرقام قاعدة البيانات. عند النقل إلى قاعدة أخرى يعيد ربط الفاتورة ببنودها والعميل والمخزن والدفعات والمدفوعات والمرتجعات بالمعرفات المحلية الصحيحة. تتضمن المعالجة معرفات نتائج المزامنة والروابط التاريخية المعروفة.

رفع النسخة نفسها مجددًا لا يكرر السجلات المعروفة، وإعادة تأكيد عملية مكتملة لا تعيد تنفيذها. كما يستخدم النظام المفاتيح الفريدة مثل كود المعرض وكود المنتج ورقم المستند لاكتشاف المطابقة أو التعارض، ولا يعتبر تشابه اسم عميل وحده دليلًا كافيًا لدمج حسابين.

### الأرصدة والنسخ الأحدث

لا تعاد خدمة بيع أو قبض لكل مستند مستعاد، ولا تجمع قيمة رصيد محفوظ فوق الرصيد الحالي. تستعاد السجلات وروابطها وأرصدتها معًا.

إذا كانت النسخة أحدث من نقطة محفوظة سابقة وكانت بيانات المعرض الحالية ما زالت تطابق تلك النقطة، يسمح بتحديث السجلات وإضافة الجديد بصورة مترابطة. إذا كانت هناك تغييرات مستقلة أو أرصدة متعارضة، تظهر التعارضات وتتوقف العملية كلها. لا يحذف الدمج بيانات حالية لفرض التطابق مع نسخة مصدر حذفت سجلات.

عند رفع نسخة قديمة معروفة وكل سجلاتها موجودة، يمكن الاحتفاظ بالبيانات الحالية الأحدث دون إرجاع أرصدتها إلى الماضي. ليست الميزة استبدالًا إجباريًا لقاعدة البيانات أو أداة لحسم تعارضين ماليين بالتخمين.

### حسابات الدخول والصور

تبقى كلمات مرور وصلاحيات ومجموعات حسابات الدخول الموجودة دون استبدال، وتستعاد الحسابات الجديدة من النسخة. تعارض اسم مستخدم مع معرض آخر يمنع الدمج.

الصور المتطابقة يعاد استخدام ملفها. وإذا حملت صورتان الاسم نفسه واختلف محتواهما، يحفظ الملف الوارد باسم آخر ويعدل رابط الصورة في السجل المستعاد، مع بقاء الصورة الحالية. لا يفك ZIP مباشرة فوق مجلد التطبيق ولا يستبدل الملفات الحالية عشوائيًا.

### الفشل والتحقق

تتحقق الأداة من صيغة النسخة وتوافق مخطط البيانات وروابط السجلات وبصمات البيانات والملفات. ترفض المسارات الخارجة والروابط الرمزية والملفات غير المعرفة والتكرارات غير الصالحة وتجاوز الحدود.

تطبق تغييرات قاعدة البيانات داخل معاملة واحدة، وتفحص العلاقات قبل اعتمادها. عند فشل العملية تتراجع تغييراتها، وتحذف الملفات التي أنشأتها المحاولة وحدها. لا يعالج الاستيراد أخطاء الحسابات التاريخية تلقائيًا؛ يمكن مراجعتها بأمر `audit_business` بعد النقل.

## الصيغة والحدود

الصيغة المدعومة للرفع هي ملف ZIP الذي تنتجه الأداة الحالية، ويحتوي `manifest.json` و`data.json` وملفات `media/`. لا تدعم هذه الشاشة رفع SQL أو SQLite أو Excel أو ملف ZIP عشوائي. ينبغي أن يتوافق إصدار بنية النسخة مع الخادم المستهدف.

القيم الافتراضية القابلة للضبط في بيئة التشغيل:

| الإعداد | القيمة الافتراضية |
|---|---|
| `BACKUP_PRIVATE_ROOT` | `private_backups` داخل مجلد المشروع، خارج المجلدات العامة |
| `BACKUP_MAX_UPLOAD_BYTES` | 536870912، أي 512 MiB |
| `BACKUP_MAX_EXPANDED_BYTES` | 2147483648، أي 2 GiB |
| `BACKUP_MAX_JSON_BYTES` | 104857600، أي 100 MiB لكل ملف JSON |
| `BACKUP_MAX_FILES` | 50000 ملف |
| `BACKUP_MAX_RECORDS` | 250000 سجل |

الحدود تطبق أيضًا عند التنزيل حتى لا تنتج الأداة ملفًا يتجاوز حد الاستيراد الحالي. تراجع حدود رفع الملفات والمهلة في خادم الويب عند ضبط أحجام أكبر. تحفظ ملفات المعاينة في مجلد خاص لا يقدم كرابط عام، وتحذف بعد اكتمال العملية؛ تنظف الملفات المنتهية عند فتح شاشة النسخ لاحقًا.

## تفعيل التحديث

بعد نشر ملفات الإصدار، مع الاحتفاظ بملف البيئة الخاص:

```powershell
python manage.py migrate
python manage.py collectstatic --noinput
```

ثم تعاد الخدمة ويحدث PWA. الترحيل الجديد هو `settings_app.0009_backup_tools`، ويضيف جداول التعريف والمعاينة والتاريخ اللازمة للنسخ، دون إعادة كتابة الأرصدة الموجودة. عمليات النسخ والدمج تحتاج اتصالًا ولا تدخل طابور الأوفلاين، وصفحاتها وملفاتها مستثناة من التخزين الخاص لـService Worker.

## التحقق

تغطي اختبارات `settings_app.tests_backups` النقل مع اختلاف الأرقام المحلية، والأرصدة والمرتجعات وروابط المزامنة، وتكرار الاستيراد، والتحديث من نسخة أحدث، ومنع تعارض الأرصدة، والتغير بعد المعاينة، وتصادم الصور، والتراجع عند فشل الملفات، والملفات التالفة والمسارات الخارجة والحدود والصلاحيات.

يشغل `tests/backups_browser_review.py` متصفح Chromium وقاعدة ووسائط اختبار مستقلة، ويختبر التنزيل ومحتوى ZIP ورفع الملف والمعاينة والتأكيد وعدم التكرار وعرض الشاشة بأربعة أحجام. لا يطبق نسخة على قاعدة التشغيل المحلية.

نتائج التحقق في 16 نوفمبر 2026:

- الفحص الشامل: نجاح 562 اختبارًا على PostgreSQL دون تخطٍّ، وتشغيل العدد نفسه على SQLite دون فشل مع تخطي خمسة اختبارات تتطلب PostgreSQL.
- اختبارات النسخ النهائية: نجاح 19 اختبارًا على PostgreSQL، وتشغيلها على SQLite دون فشل مع تخطي اختباري التزامن. تشمل تنزيل نسختين متزامنتين وتأكيد الاستيراد نفسه من طلبين متزامنين، وإعادة ربط سجل كتالوج أُعيد إنشاؤه دون استبداله بنسخة قديمة.
- نجاح 41 اختبار JavaScript، ومنها استبعاد صفحات النسخ من التخزين دون اتصال.
- نجاح مراجعة Chromium للتنزيل والرفع والتأكيد وأربعة أحجام عرض، دون أخطاء JavaScript.
- نجاح فحوص Django، واتساق الترحيلات، وصياغة Python، والتحليل الثابت للأخطاء والمراجع غير المعرفة.

استُخدمت قواعد ومرفقات اختبار منفصلة، وتسريع لكلمات مرور الاختبارات فقط دون تغيير سياسة كلمات مرور التطبيق. لم تنفذ اختبارات الدمج عملية دمج على قاعدة البيانات الأصلية أو خادم إنتاج.

## إصلاح تنزيل HTML وتوقف التنزيل — 16 نوفمبر 2026

كان زر التنزيل يحتوي خاصية `download`، ولذلك كان المتصفح قد يحفظ صفحة HTML عند فشل تجهيز النسخة وإعادة التوجيه إلى صفحة الخطأ. كذلك كانت طلبات النسخ تمر عبر مهلة تنقل PWA البالغة ثماني ثوانٍ، رغم استثنائها من التخزين المؤقت.

أصبح التنزيل انتقالًا عاديًا يترك اسم الملف وصيغته لرأس `Content-Disposition` عند نجاح تجهيز ZIP. يستثني نظام التبويبات مسارات التنزيل وملفات ZIP، وتتجاوز طلبات النسخ Service Worker بالكامل، فلا يقطعها مؤقت صفحات الأوفلاين ولا يستبدلها بصفحة HTML. وتظهر رسالة تهيئة واضحة عند عدم اكتمال ترحيلات قاعدة البيانات، مع تعطيل التنزيل والرفع حتى اكتمال التحديث.

في مساحة العمل المحلية كانت خمسة ترحيلات معلقة، منها جداول النسخ الاحتياطي. حُفظت نسخة أمان من SQLite والصور أولًا، واختبر التحديث على نسخة مستقلة، ثم طبقت الترحيلات المحلية بعد التحقق منها. أظهرت مقارنة السجلات السابقة بقاء قيمها كما هي. أنشئت بعدها نسخة ZIP من البيانات المحلية وفحصت بصمات البيانات والمرفقات وCRC للأرشيف؛ شملت 412 سجلًا وسبعة ملفات وسائط. لا يعني ذلك نشر التحديث على أي خادم خارجي.

نجح اختبار Chromium مع Service Worker فعّال وتنزيل مؤخر لأكثر من ثماني ثوانٍ، وفحص ZIP، ومحاكاة فشل التجهيز مع ظهور رسالة دون تنزيل HTML. ونجح 21 اختبارًا للنسخ على PostgreSQL دون تخطٍّ، وتشغيلها على SQLite دون فشل مع تخطي اختباري التزامن، و42 اختبار JavaScript تشمل تجاوز التبويبات وService Worker لمسار التنزيل. كما اختبرت استجابة التنزيل على البيانات المحلية بعد تحديثها، وطابق حجم ZIP رأس Content-Length ونجح فحص الأرشيف وصوره السبع.

```powershell
python manage.py test settings_app.tests_backups
python tests/backups_browser_review.py
```

## رسائل فشل التجهيز وتنبيهات البريد

أصبحت أخطاء التجهيز تعرض في الصفحة برسالة ثابتة ورقم متابعة مرتبط بسجل الاستثناء والبريد، مع صفحة بديلة إذا تعذر تحميل الواجهة بسبب قاعدة البيانات. وتعرض الشاشة نقص إعدادات SMTP أو سبب فشل الإرسال بدل اختفاء الخطأ. أصلح أيضًا تفسير حقول JSON ذات المفتاح `path` كصور أثناء إنشاء النسخة.

تفاصيل التشخيص والإعداد والتفعيل واختبارات البريد في [تقرير أخطاء النسخ وتنبيهات البريد](backup-errors-email-ar.md). يوفر الإصدار الأمرين `python manage.py check_backups --create` و`python manage.py check_error_email --connect` لفحص بيئة الاستضافة نفسها. لا يغني نجاح الاختبارات المحلية عن نشر الملفات وإعادة تشغيل التطبيق وضبط البريد الخاص على الخادم.
