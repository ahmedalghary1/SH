## 1. تعريف النظام وخريطة الأقسام

النظام يجمع دورة بيع الملابس وإدارة المخزون والتحصيل والمشتريات والمرتجعات في تطبيق واحد. الوحدة المخزنية الأساسية هي **تنويعة المنتج**: المنتج مع اللون والمقاس؛ ولذلك يمكن متابعة رصيد كل لون ومقاس في كل مخزن، مع عرض مجمع للمنتج عند الحاجة.

يدعم النظام البيع القطاعي والجملة، عدة مخازن ومعارض، عهد المندوبين، حسابات العملاء والموردين، وحساب تكلفة البضاعة والربح وفق البيانات المسجلة. الواجهة الأساسية عربية من اليمين إلى اليسار، وتناسب العمل من الكمبيوتر والهاتف.

| القسم | المميزات الأساسية | المسار الرئيسي |
|---|---|---|
| الرئيسية | مؤشرات واختصارات تختلف بحسب الدور | `/` |
| المستخدمون والمعارض | حسابات المستخدمين والأدوار والفروع وتحديد نطاق البيانات | `/accounts/` |
| المنتجات | كتالوج المنتجات وتنويعاتها والأسعار والاستيراد | `/products/` |
| المخازن | الأرصدة والدخول والخروج والتحويلات والعهدة وسجل الحركة | `/inventory/` |
| المبيعات | إنشاء مستندات البيع وتعليقها وتأكيدها ومتابعة حالتها | `/orders/` |
| الفواتير | عرض الفاتورة والتحصيل والطباعة والتصدير والإلغاء المنضبط | `/invoices/` |
| العملاء | بيانات العملاء وكشوف الحساب والتفاعلات والمتابعة | `/customers/` |
| المشتريات | الموردون وطلبات الشراء والاستلام والسداد ومرتجع الشراء | `/purchases/` |
| المالية | الخزن والحسابات وحركات القبض والصرف والتحويل والكشوف | `/finance/` |
| المرتجعات | مرتجع كلي أو جزئي واستبدال وتسوية مالية ومخزنية | `/returns/` |
| المندوبون | العهدة والكميات المباعة والمرتجعة والتحصيل والتوريد | `/sales-reps/` |
| التقارير | تحليل المبيعات والأرباح والمخزون والمديونيات والأداء | `/reports/` |
| الإعدادات | بيانات الشركة والفواتير والطباعة وسياسة الخصم | `/settings/` |
| سجل المراجعة | تتبع التغييرات والمستخدم والتوقيت | `/audit/` |
| المزامنة | تنزيل البيانات ورفع العمليات المحلية ومنع التكرار | `/api/` |

### ترابط دورة العمل

| العملية | أثرها الأساسي |
|---|---|
| تعريف منتج وتنويعاته | تجهيز الكتالوج والأكواد والأسعار؛ لا يعني وحده إضافة مخزون |
| استلام شراء أو تسجيل دخول مخزن | زيادة الرصيد وإنشاء دفعات بتكلفتها، مع تسوية السالب في المخزن نفسه |
| تحويل بين مخزنين | خروج من المصدر ودخول إلى الوجهة مع الحفاظ على تكلفة الدفعات |
| تأكيد بيع | خصم الكمية وتثبيت تكلفة البيع وتسجيل المدفوع والمتبقي |
| قبض من عميل | زيادة الحساب النقدي المناسب وتسوية الدين أو إنشاء رصيد دائن بحسب الحالة |
| إكمال مرتجع | تسوية قيمة البيع، وإعادة السليم المسموح بإعادته للمخزون، ومعالجة النقد أو الرصيد |
| توريد تحصيل مندوب | نقل المال من عهدته النقدية إلى حساب الإدارة دون تحصيل العميل مرة ثانية |

شراء الخام مسار مالي لتسجيل شراء خام من مورد، ولا يمثل دورة تصنيع أو تحويل خام إلى منتج آليًا.

## 2. الهوية والأسماء والشعارات والألوان والخطوط

### 2.1 الأسماء المستخدمة حاليًا

الهوية الحالية موزعة بين اسم المشروع واسم التطبيق ونصوص الواجهة وبيانات الشركة. القيم التالية مأخوذة من الملفات، وليست اقتراحًا لهوية جديدة:

| الموضع | النص أو الهوية الموجودة |
|---|---|
| اسم المشروع في المستودع | **SH ERP** |
| اسم التطبيق عند التثبيت | **SH لإدارة المعرض** |
| الاسم المختصر في PWA | **SH** |
| العنوان أعلى القائمة الجانبية | **إدارة الملابس** |
| الوصف أسفل عنوان القائمة | **مبيعات ومخازن** |
| العلامة الرسومية في القائمة وتسجيل الدخول | الحرف العربي **م** داخل عنصر ملون |
| وصف شاشة الدخول | **نظام إدارة الملابس والمخزون والطلبات** |
| اسم الشركة الافتراضي عند غياب التخصيص | **شركة الملابس** |
| العبارة في رأس الإيصال | **Fashion for You** |

اسم الشركة وبيانات التواصل والرقم الضريبي والشعار المرفوع قابلة للحفظ ضمن إعدادات الفرع. لا يُستنتج الاسم القانوني للشركة من اسم المستودع أو اسم ملف الصورة.

### 2.2 ملفات الشعار وأيقونات التطبيق

- يوجد أصل شعار باسم [sh-family-Logo.png](../static/images/sh-family-Logo.png).
- قالب عرض الفاتورة وقالب الإيصال يستدعيان هذا الملف الثابت مباشرة.
- طباعة تقرير الفواتير تستخدم الشعار المرفوع في إعدادات الشركة إذا كان موجودًا، وتعرض علامة «م» عند غيابه.
- أيقونتا التثبيت موجودتان بمقاسي [192 × 192](../static/icons/icon-192.png) و[512 × 512](../static/icons/icon-512.png).

**ملاحظة تخص توحيد الهوية:** رفع شعار من الإعدادات لا يستبدل تلقائيًا الشعار الثابت في جميع قوالب الفواتير. كذلك تختلف تسمية التطبيق عن عنوان الواجهة، وتوجد عبارة إنجليزية ثابتة في الإيصال. هذه أوصاف للوضع الحالي ينبغي مراعاتها عند تخصيص النسخة باسم تجاري واحد.

### 2.4 الخطوط واللغة

- الخط الأساسي **Cairo**، بأوزان 400 و600 و700.
- ملفات الخط محفوظة محليًا داخل المشروع، بما يخدم تجهيز الواجهة للعمل دون اتصال.
- توجد خطوط بديلة للنظام مثل Segoe UI وRoboto وsans-serif.
- الصفحة الأساسية معرفة باللغة العربية `lang="ar"` والاتجاه `dir="rtl"`.
- محاذاة النصوص إلى اليمين، مع أحجام خطوط متجاوبة وتباعد أسطر مقداره 1.6 في الواجهة الأساسية.
- قالب طباعة الفاتورة يستخدم Tahoma وArial؛ لذلك قد يختلف شكل خط الورق عن شاشة التطبيق.
- ملفات PDF تستخدم معالجة للنص العربي واتجاهه ضمن أدوات التصدير.
- المنطقة الزمنية المعرفة في إعدادات المشروع هي **Africa/Cairo**.

### 2.5 أسلوب تصميم الواجهة

التصميم قائم على قائمة جانبية وشريط علوي ومساحة محتوى بها بطاقات ونماذج وجداول. تستخدم العناصر زوايا مستديرة وظلالًا خفيفة وحدودًا فاتحة. تتدرج الزوايا الأساسية بين `0.375rem` و`0.875rem`، وتستخدم المسافات وحدات تصميم مشتركة.

الأيقونات رسومات SVG مشتركة داخل المشروع، بأسلوب خطوط وحدود مستديرة؛ ويتغير لون بعضها بحسب القسم. توجد حالات تركيز لعناصر الإدخال، وعناوين وصفية للأزرار الأيقونية، ودعم للوحة المفاتيح في صفوف تفاصيل حركة المنتج.

المصادر المباشرة للهوية هي [ملف التصميم الرئيسي](../static/css/main.css)، و[القالب الأساسي](../templates/base.html)، و[القائمة الجانبية](../templates/partials/sidebar.html)، و[شاشة الدخول](../templates/accounts/login.html)، و[تعريف PWA](../static/manifest.json).

## 3. تجربة الاستخدام والتنقل

- قائمة جانبية بأقسام وروابط تختلف حسب دور المستخدم، مع وضع مناسب للشاشات الصغيرة.
- شريط علوي يعرض المستخدم ودوره وفرعه، والتاريخ والوقت، وحالة التثبيت والمزامنة والعمليات المعلقة.
- تبويبات داخل مساحة العمل لفتح أكثر من شاشة والتنقل بينها، مع الاحتفاظ بحالة النموذج أثناء التبديل بين التبويبات المفتوحة.
- إمكانية فتح رابط في تبويب عمل إضافي، مع تنبيه عند مغادرة نموذج يحتوي تغييرات غير محفوظة.
- جداول بها ترقيم صفحات وعدد سجلات، وبحث وفلاتر بحسب كل شاشة.
- التحكم في إظهار أعمدة بعض الجداول وحفظ تفضيلات العرض في المتصفح.
- حقول بحث واختيار للمنتج والعميل والمخزن بدل الحاجة إلى كتابة معرفات داخلية.
- البحث عن الأصناف بالاسم والكود والباركود في المسارات التي تدعم ذلك، مع معالجة لتطبيع البحث العربي.
- رسائل واضحة لنجاح العمليات أو رفضها، وصفحات أخطاء تحتوي مرجعًا يساعد في تتبع المشكلة.
- تنسيقات للطباعة تخفي أدوات التنقل وتعيد ترتيب المحتوى المطبوع.

تفضيلات الجدول والتبويبات إعدادات واجهة محلية، بينما البيانات التجارية المعتمدة تُحفظ في قاعدة الخادم بعد نجاح العملية أو المزامنة.

## 4. المستخدمون والفروع والصلاحيات

### 4.1 إدارة المستخدمين والمعارض

- إنشاء المستخدم وتعديل بياناته ودوره وفرعه وحالته النشطة.
- تعطيل المستخدم عند انتهاء عمله، مع قيود على حذفه إذا كان مرتبطًا بسجلات تجارية أو مالية.
- لكل فرع اسم وكود فريد وعنوان وهاتف وحالة نشاط.
- المستخدم العادي مرتبط بفرع، وتُقيد البيانات والعلاقات التجارية بنطاق الفرع.
- المستخدم الأعلى `superuser` يمكنه إدارة الفروع واختيار فرع أو عرض النطاق العام وفق واجهات النظام.
- المدير ومسؤول النظام يحصلان على الصلاحيات الإدارية العامة؛ لكن الحذف النهائي له قيد إضافي.

### 4.2 الأدوار الفعلية

| الدور | ما يتيحه حاليًا | أهم القيود |
|---|---|---|
| مسؤول النظام `manager` | إدارة العمليات والإعدادات والمستخدمين والتكاليف والأرباح | الحذف خاضع لترابط السجلات وحالة المستند |
| المدير `director` | الصلاحيات الإدارية والتشغيلية العامة وعرض الأرباح والتكاليف | لا يملك الحذف النهائي المخصص لمسؤول النظام أو superuser |
| مندوب مبيعات `sales` | بيع، قبض موجب، عرض كشف العميل، إضافة منتج جديد، عرض رصيد عهدته وفواتيره | نطاق العملاء والعهدة والفواتير مقيد؛ لا يدير المرتجعات أو المشتريات أو الإعدادات |
| مسؤول مخزن `warehouse` | قراءة المنتجات والأرصدة، دخول وخروج وتحويلات، تسليم واستلام عهدة، واستلام شراء وتقارير مخزنية مسموحة | لا يملك صلاحيات الإدارة المالية العامة أو الأرباح أو تعديل إعدادات الشركة |
| المستخدم الأعلى `superuser` | صلاحيات عامة وإدارة الفروع واختيار نطاقها | تبقى قواعد صحة المستندات وترابط البيانات مطبقة |

الأدوار المذكورة ثابتة في الكود. لا توجد واجهة عامة لبناء أدوار مخصصة بصلاحيات اعتباطية، ولا دور مستقل باسم «محاسب» ضمن الأدوار الأربعة المعرفة.

### 4.3 نطاق المندوب بالتحديد

1. يسجل حركة بيع ويؤكد مسوداته، ويعرض فواتيره ويطبعها ويضيف المقبوضات المسموحة.
2. يستطيع التخلص من مسودته المعلقة غير المرحلة وغير المدفوعة وفق شروطها.
3. يسجل **قبضًا موجبًا** من عميل مسموح له برؤيته.
4. يعرض كشف حساب العميل دون تعديل أو حذف من داخل الكشف.
5. يرى العملاء المسندين إليه، بالإضافة إلى العملاء العامين غير المسندين لمندوب؛ وتُحجب عنه حسابات العملاء المسندين لغيره.
6. يسجل منتجًا جديدًا من النموذج المخصص، ويرى رصيد عهدته.
7. البيع بالسالب متاح من عهدته النشطة فقط، وفق السياسة الموضحة في قسم المندوبين.

لا يتيح دوره تعديل العملاء أو CRM، أو تعديل المنتجات الموجودة، أو تحويل المخزون، أو تسوية الجرد، أو إنشاء مشتريات، أو صرف رد نقدي أو خصم مسموح، أو إلغاء وتعديل الفواتير المرحلة. تُطبق هذه الحدود على طلبات الخادم وواجهات المزامنة، إلى جانب إخفاء الروابط في الواجهة.

## 5. لوحات المتابعة

### لوحة الإدارة

تجمع مؤشرات المبيعات وصافي الربح والتحصيل والمديونيات وأرصدة الحسابات، مع تنبيهات انخفاض المخزون وإمكانية تضييق بعض التنبيهات حسب المخزن. وتوفر اختصارات لمسار العمل: شراء خام، إضافة منتج، إدخال مخزون، فاتورة بيع، مرتجع، وفواتير.

### لوحة المخزن

تعرض الطلبات قيد التجهيز، والأصناف منخفضة الرصيد، وأحدث الحركات المخزنية. وتوفر اختصارات للدخول والتحويل وتسليم المندوب والمنتجات والأرصدة.

### لوحة المندوب

تركز على البيع السريع، وفاتورة جديدة، والقبض، وكشف حساب العميل، والفواتير، وتسجيل منتج جديد، مع مؤشرات عن مبيعاته وأحدث طلباته. لا تمنحه المؤشرات صلاحية الوصول إلى عمليات الإدارة المحجوبة عنه.

## 6. المنتجات والألوان والمقاسات والأسعار

### 6.1 بطاقة المنتج والتنويعات

- بيانات المنتج تشمل الاسم والكود والتصنيف والوصف والخامة والموسم/السنة والصورة وحالة النشاط.
- أسعار قطاعي وجملة، وعدد القطع في الدستة، والافتراضي 12 قطعة.
- تصنيفات تدعم علاقة تصنيف رئيسي وفرعي.
- تعريف ألوان بأسمائها وقيم ألوان اختيارية، ومقاسات بترتيب عرض.
- تنويعات للمنتج تجمع اللون والمقاس، ولها كود وباركود وصورة اختيارية وتكلفة وأسعار وحالة نشاط.
- أكواد المنتجات وأكواد التنويعات لها قيود عدم تكرار داخل الفرع.
- إنشاء وتعديل وإيقاف المنتج أو التنويعة حسب الصلاحية.
- نموذج إنشاء المنتج الإداري يدعم إعداد التنويعات والكميات الافتتاحية المرتبطة بمخزن، ضمن التحقق المخزني.
- صفحات لتفاصيل المنتج ومتابعة حركته وأرصدته.

التعطيل يحافظ على التاريخ. الحذف النهائي يتوقف عند وجود أرصدة أو حركات أو مستندات مرتبطة لا تسمح بالحذف.

### 6.2 الأسعار والإدخال السريع

- تعديل أسعار المنتجات والتنويعات، وتحديث أسعار مجموعة أصناف من شاشة مخصصة.
- الاستفادة من نوع البيع جملة/قطاعي لاختيار السعر المناسب في مسار الفاتورة.
- إنشاء سريع للتصنيف واللون والمقاس والمخزن في المسارات الإدارية المخصصة.
- إنشاء سريع لمنتج أو مورد من نموذج الشراء، لتقليل الانتقال بين الشاشات.
- إخفاء التكلفة والربح عن الأدوار غير الإدارية في واجهاتها ومسارات بياناتها.

وجود حقل باركود والبحث به يتيح استخدام الكود داخل النظام؛ ولا يعني وجود تكامل مستقل مع كل جهاز ماسح أو نظام توليد ملصقات.

### 6.3 استيراد المنتجات من Excel

الاستيراد الحالي يقرأ ملف **XLSX أو XLSM** من الورقة النشطة، بحد أقصى **5000 صف بيانات**. يتوقع أعمدة: «م، الكود، اسم الصنف، سعر القطعة الرئيسي، الجملة، القطاعي، السنه»، مع قبول بعض الصيغ البديلة لعناوين الأعمدة.

يتحقق المستورد من الأكواد والأسماء والأسعار، ويعالج الأرقام العربية والفارسية وبعض تنسيقات الأسعار، ويحاول الحفاظ على الأصفار البادئة في الأكواد المنسقة داخل Excel. يوضح عدد المنتجات المضافة والصفوف المتخطاة وأسباب الأخطاء، ويتجاوز المكرر بدل إنشاء نسخة أخرى منه. ينشئ المنتج وتنويعته الأساسية داخل معاملة لكل صف؛ فلا يترك نصف منتج عند فشل الصف.

الملف مخصص لتعريف المنتجات والأسعار، ولا يُعد استلام شراء أو استيرادًا تلقائيًا لكميات المخزون. ويتطلب رفع الملف اتصالًا بالخادم وصلاحية إدارية.

## 7. المخازن والمخزون وحركة الصنف

### 7.1 تعريف المخازن والأرصدة

- مخازن رئيسية ومخازن معرض ومخازن عهدة مندوب، مع عنوان وحالة نشاط ومستخدم مسؤول عند الحاجة.
- رصيد مستقل لكل تنويعة في كل مخزن، وحد أدنى يستخدم لتنبيه انخفاض المخزون.
- فلاتر وبحث بالمخزن والمنتج والتصنيف واللون والمقاس بحسب الشاشة.
- عرض رصيد المندوب من مخزن عهدته المسموح، وإظهار الأرصدة الموقعة عند السماح بالسالب.
- الاحتفاظ بدفعات المخزون: الكمية المستلمة والمتبقية وتكلفة الوحدة والمصدر والتاريخ والملاحظات.

### 7.2 العمليات المخزنية

| العملية | السلوك |
|---|---|
| دخول مخزن | زيادة رصيد تنويعة وتوثيق مصدرها وتكلفتها |
| خروج مخزن | تخفيض رصيد مع تحقق الكمية المتاحة في المسارات العادية |
| تحويل | نقل كمية من مخزن مصدر إلى وجهة مع تتبع جانبي الحركة |
| تحويل متعدد السطور | حتى 100 سطر، مع تجميع الكميات المتكررة للصنف قبل التحقق |
| تسوية مخزون | تسجيل الفرق بضوابط وصلاحية إدارية |
| تسليم عهدة | نقل المخزون إلى عهدة المندوب وتوثيق التكليف |
| استلام عهدة | إعادة الباقي من عهدة المندوب إلى المخزن |
| استلام شراء | إضافة المستلم الفعلي كدفعات بتكلفة الشراء |
| بيع ومرتجع واستبدال | حركات مخزنية مرتبطة بالمستند التجاري |

التحويل المتعدد ينفذ كوحدة واحدة: إذا فشل سطر لا تعتمد بقية السطور وحدها. وتُحفظ تكلفة الدفعات أثناء التحويل. تعتمد تكلفة البيع المتاح على **FIFO**؛ أي استهلاك الأقدم من الدفعات أولًا، مع تثبيت تكلفة البيع الفعلية في سطر المستند.

### 7.3 تقرير حركة المخزن المجمع

في تقرير `/reports/stock-movement/` يظهر **كل منتج مرة واحدة** بعد جمع حركاته المطابقة للفلاتر، بما يشمل تنويعاته. يتم التجميع قبل تقسيم الصفحات، حتى لا يتكرر المنتج بسبب وجود حركاته في صفحات مختلفة.

الصف المجمع يوضح بيانات المنتج وملخص الدخول والخروج والرصيد الحالي وأحدث حركة بحسب العرض والفلاتر. الضغط على الصف يفتح تفاصيل حركة المنتج داخل قسم المخزن، مع الاحتفاظ بفلاتر السياق. توجد أيضًا روابط للوصول إلى التفاصيل من صفوف الأرصدة والحركات للمستخدم المصرح له.

### 7.4 تفاصيل حركة المنتج

توجد شاشة `/inventory/movements/products/<pk>/` لعرض جميع مرات دخول وخروج المنتج، مع اللون والمقاس والمخزن ونوع الحركة والتاريخ والمستخدم والملاحظات وتغير الرصيد. تعرض التفاصيل الرصيد قبل الحركة وبعدها وفق سياق المخزن.

عند عرض جميع المخازن يمكن متابعة طرفي التحويل؛ وعند تحديد مخزن تظهر الحركة من منظوره. تدعم الشاشة البحث والتواريخ والترقيم ومسح الفلاتر. الرصيد الموسوم بأنه **حالي** يبقى رصيد الوقت الحالي حتى عند تصفية الحركات بتاريخ؛ أما تفاصيل تسلسل الحركة فتُستخدم لفهم تغير الرصيد عبر الزمن.

## 8. المبيعات والطلبات وعروض السعر

### 8.1 المستندات وإعداد البيع

- مستند بيع عادي، وعرض سعر، وصرف عينة مجانية في المسارات الإدارية المسموحة.
- بيع جملة وقطاعي، واختيار العميل عند الحاجة؛ بيانات العميل مطلوبة في بيع الجملة والبيع الآجل.
- تاريخ ووقت للفاتورة يمكن تحديدهما من النموذج.
- بحث واختيار المنتج والتنويعة، وتحديد مخزن الصرف لكل سطر بحسب الصلاحية.
- إضافة عدة أصناف وكميات وأسعار، مع تحويل القطعة/الدستة اعتمادًا على عدد القطع المحدد للمنتج.
- اختيار دفعة مخزون في المسارات التي تعرض ذلك، أو استخدام التخصيص المعتاد للدفعات.
- خصومات للصنف وخصم عام، وحساب فوري للإجماليات؛ توجد معالجة للقيمة والنسبة في منطق الحساب، بينما النموذج الحالي يبسط إدخال الخصم العام بالقيمة.
- حفظ الطلب كمسودة/فاتورة معلقة ثم استكماله أو تأكيده لاحقًا.

عروض السعر والمسودات غير المؤكدة لا تخصم المخزون كبيع مرحل. يقتصر المندوب على البيع المسموح، ولا يستعمل صلاحية العينة المجانية أو عرض السعر عبر مسار المبيعات المقيد.

### 8.2 طرق الدفع والحالة

خيارات نموذج البيع الحالي هي **نقدي، تحويل عبر محفظة، وآجل**. يسجل التحويل عبر المحفظة أرقام المحافظ المطلوبة؛ وهو تسجيل يدوي للحركة، وليس اتصالًا ببوابة دفع تنفذ التحويل تلقائيًا.

يوجد تتبع للمدفوع والمتبقي وحالة الدفع: غير مدفوع، جزئي، أو مدفوع. ويتضمن مسار الطلب حالات المسودة والتأكيد والتجهيز والجاهزية والإكمال والإلغاء والمرتجع الجزئي أو الكلي، بحسب الانتقالات المسموح بها.

### 8.3 قواعد الحساب والتأكيد

1. حساب قيمة السطور والخصومات وصافي الفاتورة مع تقريب نقدي إلى قرش.
2. الحفاظ على مدخل الخصم منفصلًا عن قيمته المحسوبة، حتى لا يتضاعف عند إعادة الحساب.
3. التحقق من الكمية المتاحة ومن تكرار الصنف داخل المستند قبل الصرف؛ مع استثناء عهدة المندوب المصرح لها بالسالب.
4. التحقق من صافي السعر بعد الخصومات مقابل تكلفة الدفعات، وفق سياسة البيع تحت التكلفة.
5. تأكيد المستند وخصم المخزون وتسجيل آثاره المالية داخل عملية مترابطة تتراجع عند الفشل.
6. ترقيم المستندات بضوابط تمنع التصادم عند الإنشاء المتزامن.

### 8.4 التعديل والإلغاء

توجد إجراءات إدارية لتعديل المستندات المسموح تعديلها، مع إعادة تسوية المخزون والمدفوعات، ورفض التعديل عند وجود مرتجعات أو تسويات مرتبطة تمنعه. كما توجد إجراءات لتحديث الحالة، وإلغاء الطلب، وحذف المسودة وفق حالتها.

تعديل أو إلغاء مستند مرحل يحتاج اتصالًا بالخادم، ولا يترك للمندوب تعديل الفاتورة المرحلة أو حذفها بعد البيع.

## 9. الفواتير والطباعة والتصدير

### 9.1 إدارة الفاتورة

- قائمة فواتير مع بحث وفلاتر وعرض تفاصيل وربط بالطلب والعميل والمستخدم.
- رقم فاتورة وتاريخ إصدار، وبنود تحتوي وصف المنتج والكود واللون والمقاس والكمية والسعر والخصم والإجمالي.
- بيانات الشركة والعميل وطريقة الدفع والمدفوع والمتبقي وحالة الدفع.
- حفظ لقطة وصفية لبيانات الفاتورة عند إصدارها، للحفاظ على أسماء وبيانات تاريخية مهمة عند تغيير الكتالوج أو الإعدادات لاحقًا.
- إضافة دفعة للفاتورة وفق قواعد التحصيل والعميل وحالتها.
- تسجيل حالة الطباعة عبر المسار المخصص.

### 9.2 أنماط الطباعة

- عرض مناسب للشاشة، وعرض إيصال للطابعة الحرارية.
- دعم مقاسي ورق **58 مم و80 مم**.
- ثلاثة أحجام خط حراري: عادي 100%، كبير 115%، وكبير جدًا 130%.
- طباعة عن طريق حوار المتصفح، وهي الطريقة الافتراضية المتاحة لتطبيق PWA.
- إعداد اسم طابعة، مع مسارات برمجية اختيارية للطباعة عبر جسر Electron أو QZ Tray عند توفيرهما في بيئة التشغيل.

وجود خياري Electron وQZ في الإعدادات لا يجعل نسخة PWA برنامج Windows مستقلًا، ولا يثبت أن جسر الطباعة أو QZ مثبت ومجهز. تعتمد الطباعة المباشرة على توفير هذا التكامل خارجيًا، ويوجد رجوع إلى طباعة المتصفح عند تعذر المسار المباشر.

### 9.3 التصدير والإلغاء

توجد صادرات **Excel وPDF** لقائمة الفواتير، وطباعة تقرير الفواتير. وتتوفر صيغ أخرى في الأقسام التي تخصص لها أزرار تصدير؛ لا تنطبق كل صيغة على كل شاشة.

عملية حذف الفاتورة التجارية المرحلة تعالج كإلغاء يحافظ على السجلات: تعيد المخزون إلى مخازنه الأصلية، وتعكس المقبوض الفعلي من حساباته، وتزيل الدين المتبقي المرتبط بالبيع. تمنعها مرتجعات مرتبطة أو تحصيلات مندوب تم توريدها حتى تسويتها. تكرار طلب الإلغاء لا يرد المخزون أو النقد مرتين، وتبقى الفاتورة وآثار المراجعة محفوظة.

## 10. العملاء وكشوف الحساب وCRM

### 10.1 ملفات العملاء

- شاشات مبسطة وأخرى تفصيلية لقائمة العميل وملفه.
- الاسم ونوع التعامل قطاعي/جملة، والهاتف الاختياري، والعنوان والملاحظات ومسؤول المبيعات.
- رصيد افتتاحي وحقل حد ائتمان للمستخدم الإداري، وحالة نشاط.
- يحتوي نموذج البيانات أيضًا على حقول واتساب وبريد واسم شركة ورقم ضريبي؛ لا تعرض كل النماذج كل هذه الحقول.
- بحث بالاسم والهاتف وبيانات أخرى بحسب الشاشة، مع فلاتر وفرز مالي.
- ربط العميل بمندوب، أو إبقاؤه عميلًا عامًا غير مسند.
- ملخص المشتريات والمدفوعات والمرتجعات والمتبقي وآخر تعامل.
- ضوابط على تعديل أو حذف الملف عند وجود علاقات مالية وتجارية تمنع ذلك.

**حد الائتمان:** يوجد حقل لحفظه؛ لا يصف هذا التقرير وجود الحقل باعتباره ضمانًا لمنع آلي شامل لكل بيع يتجاوزه، إذ لا يظهر تطبيق عام له في مسار البيع الحالي.

### 10.2 كشف حساب العميل

الكشف يجمع الرصيد الافتتاحي والفواتير والمقبوضات والمرتجعات والتسويات، مع مدين ودائن ورصيد متحرك وتاريخ ومرجع لكل حركة. توجد فلاتر تاريخ وتصدير PDF وExcel في المسار المخصص.

يعالج الرصيد دين الفواتير الفعلي مع الحركات التي تؤثر في حساب العميل. يمكن توزيع القبض على المستحقات، وتسوية الافتتاحي، والاحتفاظ بزيادة القبض كرصيد دائن بحسب نوع العملية، مع فصل أثر القبض النقدي عن سطور توزيعه حتى لا يدخل المال مرتين.

المندوب يقرأ كشف العملاء المسموحين فقط، ولا يعدل أو يحذف من الكشف. وفي وضع عدم الاتصال يعرض التطبيق آخر كشف تم تنزيله مضافًا إليه أثر البيع والقبض المحليين المعلقين، مع بيان حداثة البيانات.

### 10.3 التفاعلات والمتابعة

- تسجيل مكالمة أو واتساب أو زيارة أو ملاحظة أو شكوى أو متابعة.
- عنوان ووصف لكل تفاعل، ومن سجله وتوقيته.
- تحديد موعد متابعة لاحق وحالة اكتمال.
- قائمة التفاعلات وسجلها لكل عميل، وشاشة متابعات اليوم.
- تعديل وحذف وإكمال التفاعل للمستخدم المصرح له.
- تقارير عن كبار العملاء والعملاء غير النشطين والمدينين والشكاوى.

التفاعل من نوع واتساب سجل للمتابعة داخل النظام؛ لا يعني إرسال رسائل تلقائية إلى العملاء. كما لا تمنح واجهات CRM للمندوب الحالي صلاحية الكتابة المحجوبة عنه.

### 10.4 مراجعة أرصدة قديمة

يوجد مسار إداري لمراجعة ارتباط مرتجعات قديمة بحساب العميل قبل تسوية محددة. يعتمد التنفيذ على بيانات مراجعة موقعة والتحقق من عدم تغيرها، ولا ينشئ تحصيلًا نقديًا وهميًا لتغطية فرق تاريخي.

## 11. الموردون والمشتريات

### 11.1 إدارة المورد

- ملف مورد ببيانات الاسم والشركة والتواصل والعنوان والملاحظات والنشاط.
- رصيد افتتاحي ورصيد حالي، وطلبات شراء ومدفوعات مرتبطة.
- شاشات مبسطة وتفصيلية، وبحث وقائمة وكشف حساب.
- إضافة سريعة للمورد من نموذج شراء البضاعة.
- حماية الحذف عند وجود مستندات أو أرصدة مرتبطة.

### 11.2 طلب شراء البضاعة

- مورد وتواريخ طلب واستلام متوقع، وعدة سطور منتجات وتنويعات وكميات وتكلفة وحدة.
- خصم شراء بالقيمة أو النسبة، وحساب الإجمالي والمدفوع والمتبقي.
- حالات تشمل المسودة والطلب والاستلام الجزئي والكامل والإلغاء.
- إنشاء منتج سريع أثناء الشراء، واختيار تنويعات مرتبطة بالتعامل مع المورد.
- استلام جزئي أو كامل في مخزن محدد؛ الاستلام وحده يضيف الكمية الفعلية إلى المخزون ودفعات التكلفة.
- سداد مستحق أمر الشراء من الحساب المناسب، مع منع دفع يتجاوز الباقي في مسار السداد المرتبط بالمستند.
- تعديل وخصم وإلغاء بضوابط تراعي ما استُلم وما دُفع والروابط القائمة.
- لا يسمح حذف مسودة غير مرحلة باعتباره طريقًا لمحو شراء مستلم أو مدفوع دون تسوية.

مجرد إنشاء طلب شراء لا يزيد المخزون. كما أن استلام البضاعة في المخزن الرئيسي لا يسوي سالب عهدة مندوب قبل تحويلها إلى مخزنه.

### 11.3 مرتجع الشراء وسداد المورد

يوجد مسار لمرتجع شراء يخصم الكمية من المخزن ويخفض مديونية المورد بحركة مخصصة. وسداد المورد قد يرتبط بطلب أو يسجل دفعة عامة، بحيث يمكن تمثيل دفعات مقدمة أو رصيد دائن وفق المعاملة.

يكشف حساب المورد أثر المشتريات والمدفوعات والمرتجعات، ويفصل الحركات التي يجب أن تغير الدين عن الحركات النقدية المحايدة له.

### 11.4 شراء الخام

يمكن تسجيل شراء خام نقدي باسم الخام والمورد والقيمة والحساب. يسجل هذا خروجًا نقديًا من نوع مستقل، ويعرض في كشف المورد بطريقة لا تترك دينًا إضافيًا مقابل شراء تم دفعه نقدًا. لا ينشئ هذا المسار مخزون خام تفصيليًا أو وصفة تصنيع أو أمر إنتاج.

## 12. الخزن والحسابات والقبض والصرف

### 12.1 الحسابات النقدية

- حسابات من أنواع خزنة نقدية وبنك ومحفظة وعهدة نقدية لمندوب.
- اسم ورصيد ومستخدم مسؤول وحالة نشاط، وإعداد السماح بالسحب على المكشوف للحساب.
- حسابات افتراضية للخزنة/الدرج وحسابات المندوبين بحسب احتياجات المسارات.
- كشف لكل حساب وحركة مالية، وشاشة لإدارة الحسابات للمخولين.

### 12.2 أنواع الحركات

| الحركة | الوظيفة |
|---|---|
| قبض عميل | تسجيل النقد وتسوية دين العميل أو رصيده |
| سداد مورد | إخراج المال وتسوية مستحق المورد |
| مرتجع مورد | تخفيض مديونية المورد كأثر مستقل لمرتجع الشراء |
| شراء خام | خروج نقدي لشراء الخام |
| مصروف | تسجيل مصروف بتاريخ الحركة وملاحظاتها وحسابها |
| رد مبلغ | معالجة صرف نقدي للعميل عند استحقاقه |
| تحصيل مندوب | تسجيل مال جمعه المندوب من العميل |
| توريد مندوب | نقل المتاح من عهدته النقدية للإدارة |
| تحويل حسابات | نقل المال بين حسابين داخل النظام |
| تسوية | حركة تعديل مسموحة حسب المسار والصلاحية |
| خصم مسموح للعميل | تخفيض مديونية غير نقدي، ولا يعامل كمال قبضه العميل أو دفعه |

### 12.3 الخزنة والوردية والكشوف

- لوحة خزنة تعرض افتتاحي الفترة والداخل والخارج وأثر المبيعات والقبض والمصروفات والسداد والردود والرصيد.
- اختيار الفترة والحساب ونوع الحركة وفلاتر أخرى بحسب الشاشة.
- شاشة وردية لمتابعة حركات المستخدم ضمن نطاقها.
- قائمة معاملات مالية مع عرض المرجع والعميل أو المورد أو الفاتورة والحساب والتاريخ.
- كشوف حساب للخزنة والعميل والمندوب.
- تقارير يومية للتحصيل، وتقارير للمصروفات.
- تعديل القبض أو المصروف وحذف المعاملة المسموح بها مع إعادة تسوية أثرها، بدل تغيير الرصيد يدويًا بلا مرجع.

### 12.4 ضوابط التسوية

يُفصل بين **الحركة التي تؤثر في المال** والحركة التي توزع المبلغ على الدين. كما يُفصل الخصم المسموح غير النقدي عن القبض. التحويل بين حسابين يسجل طرفيه معًا، ويتحقق من الحساب والرصيد والسياسة؛ ولا ينجح طرف ويفشل الآخر.

المندوب يسجل القبض الموجب فقط، ولا يستخدم نماذج الرد أو الخصم المسموح أو التحويل. عمليات الإدارة المالية الحساسة تتطلب صلاحياتها واتصالها المعتاد.

هذه إمكانات لإدارة المال والمديونيات التشغيلية، ولا تمثل وحدها دليل حسابات ودفتر أستاذ عام أو نظام قوائم مالية قانونية متكامل.

## 13. مرتجعات البيع والاستبدال

### 13.1 إنشاء المرتجع ودورة اعتماده

- إنشاء مرتجع من فاتورة أو بالاعتماد على تاريخ مشتريات العميل، مع مسارات مبسطة وتفصيلية.
- اختيار المنتج والكمية والسبب والتاريخ والمخزن المستهدف.
- منع إرجاع أكثر من الكمية المتاحة بعد المرتجعات السابقة.
- تحديد حالة القطعة سليمة أو تالفة، وهل يعاد السليم إلى المخزون.
- حفظ مسودة ثم اعتماد وإكمال، أو رفض وإلغاء بحسب حالة المستند والصلاحية.
- تعديل المرتجع المسموح مع التحقق من نسخته لتفادي اعتماد تعديل قديم فوق تعديل أحدث.
- تقارير أسباب المرتجعات والأصناف المرتجعة والمرتجعات اليومية.

### 13.2 الحساب المالي للمرتجع

قيمة المرتجع تعتمد صافي البيع بعد خصومات الصنف ونصيبه من الخصم العام. وتعالج المرتجعات الجزئية فروق التقريب بحيث لا يتجاوز مجموع الردود قيمة البيع المستحقة.

تسوى القيمة مع المتبقي على العميل أولًا بحسب مسار العملية، ثم يعالج الرصيد المستحق كنقد أو كتسوية حسابية/رصيد دائن وفق الخيار المسموح. ويمكن ربط التسوية بفواتير أخرى للعميل عندما يدعم المسار ذلك. الخصم المسموح غير النقدي لا يتحول إلى رد نقدي وكأنه مبلغ دفعه العميل.

### 13.3 الأثر المخزني والاستبدال

- تعود القطع السليمة إلى الرصيد عند اختيار إعادتها للمخزون.
- يسجل التالف دون زيادة الرصيد الصالح للبيع.
- يحتفظ النظام بتتبع حركة العودة وتكلفتها المرتبطة بعملية البيع بحسب البيانات المتاحة.
- الاستبدال يضيف أصنافًا بديلة ويصرفها، ويحسب فرق القيمة والمديونية أو الرد.
- لا يكتمل الاستبدال قبل استيفاء كميات الاستبدال المطلوبة والتحقق من مخزون البدائل.
- إلغاء المرتجع يعكس آثاره المخزنية والمالية ضمن شروط الروابط والتكرار.

يوجد إجراء إداري مخصص لمراجعة رد قديم صُرف بالخطأ عن فاتورة غير مدفوعة وتحويله إلى التسوية المناسبة بعد مراجعة محمية من تغير البيانات. لا يعمل كإصلاح جماعي صامت لكل الأرصدة.

## 14. إدارة المندوبين والعهدة والبيع بالسالب

### 14.1 إدارة عهدة البضاعة والتحصيل

من جهة الإدارة أو المخزن المصرح له توجد شاشة متابعة للمندوب وعهدته، وسجلات تسليم أصناف، وتسجيل المباع، وإعادة المتبقي. تتتبع العهدة الكمية المسلمة والمباعة والمرتجعة والباقية.

من جهة الإدارة المالية توجد تحصيلات المندوب ومبالغها وما وُرد منها والمتبقي للتوريد، وكشف حساب وتقارير للعهدة والتحصيل. يدعم التوريد الجزئي، ويمنع توريد أكثر من المتاح غير المورد، ويسجل انتقال المال بين الحسابات المناسبة دون تكرار القبض من العميل.

هذه واجهات إدارة المندوبين؛ لا تعني أن حساب المندوب نفسه يستطيع تسليم بضاعة لنفسه أو تحويل مخزون أو توريد عبر كل صفحات الإدارة. واجهته اليومية محددة بالبيع والقبض والكشف وإضافة المنتج ورصيد عهدته.

### 14.2 تسجيل منتج جديد بواسطة المندوب

يوجد نموذج مخصص لتسجيل اسم وكود المنتج والأسعار، مع لون ومقاس وتكلفة تقديرية اختيارية حسب النموذج. يبدأ المنتج دون إنشاء بضاعة وهمية، ويمكن بيعه من عهدة المندوب بالسالب. إذا كان الكود موجودًا بالفعل يُستخدم الصنف الموجود بدل نسخه كمنتج جديد.

في وضع عدم الاتصال تُنشأ معرفات محلية للمنتج والتنويعة. وعند المزامنة يعتمد إنشاء المنتج قبل الفاتورة التي تستخدمه، ثم تستبدل المراجع المحلية بمراجع الخادم المقبولة.

### 14.3 متى يسمح بالسالب؟

الاستثناء خاص **ببيع عادي مؤكد من مخزن عهدة نشط مسند إلى المندوب نفسه**. لا يمنحه مخزون مخزن آخر، ولا يسمح بتجاوز قواعد العينات المجانية أو التحويلات أو التعديل اليدوي للأرصدة. المسارات العادية للمدير والمخزن تظل خاضعة للتحقق من التوفر.

### 14.4 كيف يتسوى السالب؟

| الخطوة | الحركة في مخزن المندوب نفسه | الرصيد الناتج |
|---|---|---|
| البداية | الرصيد صفر | 0 |
| بيع قبل تسجيل الاستلام | بيع 10 قطع | -10 |
| تسجيل استلام أول | دخول 6 قطع | -4 |
| تسجيل استلام لاحق | دخول 10 قطع | 6 |

الوارد يسوي الجزء السالب أولًا، وتبقى ست قطع فقط كدفعات متاحة للبيع في المثال. إذا دخلت البضاعة إلى المخزن الرئيسي، فلا بد من تحويلها إلى عهدة المندوب حتى يتغير رصيده. إنشاء فاتورة شراء بلا استلام، أو الاستلام في مخزن مختلف، لا يسوي سالب عهدته.

**أثر التكلفة:** عند بيع كمية لا توجد لها دفعات متاحة تستخدم تكلفة الصنف الحالية كتقدير. تسجيل الشراء لاحقًا يسوي الكمية ويحدد تكلفة الوارد الجديد، لكنه لا يعيد حساب ربح كل فاتورة بيع قديمة تلقائيًا.

| تحصيلات المندوبين | متابعة التحصيل والتوريد والمتبقي |

### 15.3 تقارير العملاء والموردين والمرتجعات والمالية

- تقرير العملاء، ومديونيات العملاء، وكبار العملاء، والعملاء غير النشطين، والشكاوى.
- تقارير المشتريات ومديونيات الموردين وكشوف حساباتهم.
- تقرير المرتجعات العام، والمرتجعات حسب السبب والمنتج واليوم.
- تقارير التحصيل اليومي والمصروفات وكشوف الحسابات النقدية والمندوبين.

تعتمد الفلاتر على التقرير نفسه: تواريخ، حالة، مستخدم، عميل، مخزن، أو صنف حيث تتوفر. كذلك يعتمد توفر Excel أو PDF أو CSV أو الطباعة على الشاشة ومسار التصدير، ولا توجد صيغة موحدة مفروضة على جميع التقارير.

### 15.4 تفسير أرقام الربح

تقارير الربح والشهور والسنوات تعرض صافي **فواتير الفترة بعد مرتجعاتها المكتملة حتى وقت العرض**. ينسب المرتجع إلى فاتورته الأصلية في هذه التقارير؛ لذلك قد تتغير قراءة شهر سابق عند إكمال مرتجع لفاتورة منه. تختار المصروفات بحسب تاريخ الحركة المالية.

تستعاد تكلفة القطع السليمة التي عادت إلى المخزون، بينما تبقى تكلفة التالف أو غير المعاد ضمن التكلفة. وعندما تكون تكلفة استبدال قديم مفقودة يمكن أن يظهر عدد سطور بتكلفة تقديرية. والبيع بالسالب له التكلفة التقديرية الموضحة سابقًا. يجب قراءة الربح على أساس هذه السياسة، لا باعتباره دفتر أستاذ مستقلًا لكل حركة بتاريخها.

## 16. تطبيق PWA والعمل دون اتصال والمزامنة

### 16.1 طبيعة النسخة المثبتة وتجهيزها

النسخة المثبتة المقصودة هي **موقع PWA** يفتح في نافذة مستقلة من أيقونة الجهاز، وليس ملف برنامج Windows مستقلًا. يحتوي تعريف التثبيت على اسم SH، واتجاه عربي، ووضع `standalone`، وأيقونات، ونطاق بدء من جذر الموقع.

يلزم الدخول أول مرة أثناء الاتصال، وتنزيل الإصدار والملفات والبيانات المصرح بها، وانتظار حالة الجاهزية. تجهيز PWA في الإنتاج يعتمد على HTTPS ومتصفح يدعم الإمكانات المطلوبة. التثبيت وتوقيت إتاحة زر التثبيت يختلفان بحسب المتصفح.

### 16.2 الأعمال الأساسية للمندوب دون اتصال

| العمل | السلوك المحلي |
|---|---|
| فاتورة بيع جديدة | تحفظ محليًا وتدخل طابور المزامنة، مع أثر الكمية والقيم |
| قبض موجب من عميل | يحفظ محليًا ويظهر أثره على الكشف المحلي |
| تسجيل منتج جديد | يحفظ المنتج وتنويعته ثم يعتمد قبل الفواتير التابعة له |
| كشف حساب عميل | عرض آخر كشف منزل مع أثر العمليات المحلية وتاريخ تحديث البيانات |
| رصيد العهدة | آخر رصيد منزل مضافًا إليه أثر عمليات الجهاز المعلقة |
| التنقل وإعادة فتح التطبيق | استخدام ملفات وصفحات مجهزة ومخزنة ضمن نطاق الحساب |
| متابعة العمليات المعلقة | عدد عمليات وحالة وأخطاء، مع إمكانية تصدير الطابور للمراجعة |

توجد أيضًا معالجات محلية لإنشاء بعض بيانات العملاء والمنتجات والحركات المخزنية والمدفوعات والمشتريات والمرتجعات للأدوار التي يسمح لها أصلًا بذلك. وجود المعالج لا يمنح المندوب إذنًا لا يملكه، ولا يجعل جميع شاشات الإدارة تعمل دون اتصال.

### 16.3 الحفظ المحلي وحماية الأرصدة

- تستخدم بيانات العمل **IndexedDB**، وتستخدم ملفات التطبيق وصفحاته المجهزة تخزين Service Worker.
- يُفصل التخزين بحسب المستخدم والفرع والدور وحالة المستخدم الأعلى، لتقييد اختلاط بيانات الحسابات.
- يحفظ السجل المحلي وطلب مزامنته داخل معاملة محلية واحدة.
- البيع المؤكد محليًا يثبت أثر المخزون مع الفاتورة والطابور؛ وإذا فشل التحقق لا تحفظ نصف عملية.
- تجمع السطور المتكررة للمنتج/المخزن عند اختبار الكمية.
- المسودات وعروض السعر لا تحجز المخزون كبيع مؤكد.
- لا يستبدل تنزيل جديد لقطة المخزون أثناء وجود عمليات معلقة أو تعارضات قد تضيع حجوزاتها المحلية.
- يُفحص وصول الخادم قبل إرسال نموذج مدعوم؛ فإذا كان الخادم غير قابل للوصول يمكن حفظ العملية محليًا حتى لو أظهر الجهاز أنه متصل بالشبكة.

### 16.4 متى وكيف ترفع العمليات؟

تجري محاولات المزامنة عند عودة الاتصال، وعودة التركيز إلى التطبيق، وبصورة دورية أثناء فتحه، ومن زر المزامنة اليدوية. تُجدد الجلسة ورمز الحماية، وتنفذ العمليات بالترتيب، مع مراعاة إنشاء المنتج قبل مستنداته التابعة.

لكل عملية مفتاح مستقل يمنع تكرار أثرها على الخادم. إذا وصل الطلب أكثر من مرة بالمفتاح نفسه والهوية والمحتوى نفسيهما يعاد ناتجه المعتمد بدل تنفيذ بيع أو قبض ثانٍ. وتتحقق المزامنة من الفرع والمستخدم والجهاز والصلاحيات، ولا تعتمد الطلب بناءً على بيانات الواجهة وحدها.

الأخطاء المؤقتة تعاد محاولتها بتأخير متزايد يصل إلى خمس دقائق. الأخطاء الدائمة والتعارضات تبقى ظاهرة وتوقف العمليات اللاحقة التي قد تعتمد عليها حتى المراجعة. يعرض حوار الطابور نوع العملية ووقتها ومعرفها والخطأ، ويدعم تصدير نسخة JSON للمراجعة.

إذا أُرسل طلب تجاري بالفعل ثم فُقد رده، لا يتحول تلقائيًا إلى طلب محلي جديد؛ فقد يكون الخادم اعتمده. تهدف هذه القاعدة إلى منع تكرار الفاتورة أو القبض بسبب فقد الاستجابة.

### 16.5 العمليات التي تحتاج اتصالًا

- أول تسجيل دخول وتجهيز أو تحديث بيانات الجهاز.
- تعديل أو إلغاء/حذف الفواتير الموجودة والعمليات المالية الموجودة.
- تعديل أو استلام أو تحديث خصم أمر شراء قائم.
- اعتماد أو إكمال مرتجع موجود، وتسويات الإدارة الحساسة.
- استيراد ملفات المنتجات، والصادرات التي يولدها الخادم.
- أي نموذج لا يملك معالج حفظ محلي مدعومًا، أو صفحة لم تُجهز للعمل دون اتصال.

### 16.6 حدود التشغيل اليومية

الفاتورة المحلية تبقى **مبدئية حتى يقبل الخادم مزامنتها**. الرصيد دون اتصال يعكس آخر تنزيل وهذا الجهاز؛ لا يعرف مبيعات الأجهزة الأخرى لحظة انقطاعه، ويعيد الخادم التحقق عند الرفع.

ينبغي إبقاء التطبيق مفتوحًا لإكمال المزامنة؛ لا يوجد ضمان بتنفيذها عندما يغلقه نظام التشغيل. كما أن مسح بيانات المتصفح أو إخلاء التخزين قد يزيل العمليات غير المرفوعة. لا تُستخدم إزالة التخزين علاجًا لمشكلة تحديث أو تعارض، ولا تتضمن نسخة قاعدة الخادم العمليات التي لم تصل إليه من جهاز المندوب.

تحديث الإصدار ينتظر التنشيط المخصص ويتحقق من العمل غير المحفوظ والطابور. التخزين القديم المشترك لا يُدمج تلقائيًا إذا تعذر إثبات مالكه وفرعه. للتفاصيل التشغيلية راجع [توثيق PWA والمزامنة](pwa_offline_sync.md).

## 18. سجل المراجعة وحماية ترابط البيانات

### 18.1 سجل التغييرات

- توثيق المستخدم ونوع الإجراء والقسم والنموذج ومعرف السجل ووصفه وتوقيته.
- حفظ معلومات قبل/بعد للتغييرات التي تسجلها آلية المراجعة، مع سياق طلب مثل عنوان IP وبيانات المتصفح عند توفره.
- شاشة بحث وفلاتر بالمستخدم والقسم والإجراء والنموذج والسجل والتاريخ.
- عرض تاريخ مرتبط بالسجل في الشاشات التي تضيفه.
- الوصول لشاشة السجل العامة يتطلب مستخدمًا إداريًا مع صلاحية دخول العاملين `is_staff` وفق مسارها الحالي.

### 18.2 ضوابط صحة العمليات

- التحقق من انتماء العلاقات للفرع الصحيح، ومن صلاحية المستخدم للسجل والعملية.
- معاملات قاعدة بيانات مترابطة للحركات التجارية والمالية الحساسة، مع أقفال صفوف في المسارات التي تحتاجها.
- حماية من تكرار إرسال النماذج، ومفاتيح عدم تكرار مستقلة للمزامنة.
- ضوابط على القيم المالية والكميات والحالات والروابط قبل اعتماد المستند.
- منع محو كيان تجاري مرتبط بمخزون أو تاريخ أو أموال في الحالات المحمية؛ مع تفضيل التعطيل أو الإلغاء الذي يحتفظ بالأثر.
- حماية جلسات ونماذج Django المعتادة، ومراقبة رفض الصلاحيات ومحاولات الدخول وفق إعدادات المشروع.

هذه ضوابط موجودة لتقليل الخطأ وحماية الترابط، ولا تعني استحالة وجود خطأ أو صحة أي رصيد قديم دون مستنداته.

### 18.3 فحص منطق العمل دون تعديل الأرصدة

يتضمن المشروع أمر `audit_business` لإنتاج تقرير مراجعة عن الفواتير والتكاليف والمدفوعات والمرتجعات وأرصدة العملاء والموردين ومطابقة المخزون مع الدفعات والعلاقات العابرة للفروع. الأمر للمراجعة ولا يصلح الأرقام تلقائيًا.

```powershell
python manage.py audit_business --output business-audit.json
```

يمكن استخدام نتيجته لتحديد المستندات المحتاجة مراجعة، ثم الرجوع للأصول قبل أي معالجة مالية منفصلة.

## 19. البنية التقنية وواجهات API والتشغيل والنسخ الاحتياطي

### 19.1 المكونات

| المكون | المستخدم في المشروع |
|---|---|
| لغة الخادم | Python، والحد المعلن للتشغيل 3.10 فأحدث |
| إطار الويب | Django، والإصدار المثبت في المتطلبات `5.2.18` |
| الواجهة | قوالب Django وHTML وCSS وJavaScript |
| قاعدة البيانات | SQLite محليًا، ودعم PostgreSQL للنشر |
| الصور | Pillow |
| Excel | openpyxl |
| PDF والعربية | ReportLab وarabic-reshaper وpython-bidi |
| الملفات الثابتة | إعدادات Django وWhiteNoise بحسب النشر |
| التطبيق المثبت | Web App Manifest وService Worker وIndexedDB |

يتوزع منطق العمل على تطبيقات منفصلة للحسابات والمستخدمين والعملاء والمنتجات والمخزون والمبيعات والفواتير والمشتريات والمرتجعات والمالية والمندوبين والتقارير والإعدادات والمراجعة والمزامنة.

### 19.2 واجهات API

- وصف مخطط API على `/api/schema/` وصفحة توثيقه على `/api/docs/`.
- تسجيل دخول وتجديد هوية وقراءة المستخدم لعملاء الرموز عبر `/api/auth/`.
- مسارات تنزيل كامل وتغييرات ودفع عمليات لعملاء المزامنة.
- مسارات متصفح منفصلة تستخدم الجلسة وCSRF، منها جلسة المزامنة وتهيئة البيانات والتغييرات.
- رفع مبيعات ومنتجات وعملاء وحركات مخزون ومال ومشتريات ومرتجعات وإجراءات مندوبين حسب الصلاحية.
- حد أقصى 100 عملية في طلب الدفع العام للمزامنة.

هذه API تخدم المزامنة والمسارات الموجودة، ولا تعني تلقائيًا وجود تكامل جاهز مع متجر إلكتروني أو شحن أو بنك أو برنامج محاسبة خارجي.

### 19.3 التشغيل والمتابعة

- إعدادات بيئة منفصلة لقاعدة البيانات والاستضافة والملفات وHTTPS والاتصالات الاختيارية.
- دعم ترحيلات قاعدة البيانات `migrations` لنشر تغييرات البنية.
- تجميع الملفات الثابتة وتقديم الصور المرفوعة وفق إعداد النشر.
- نقطة `/health/` تفحص اتصال قاعدة البيانات والترحيلات وصلاحية الكتابة للوسائط والمساحة المتاحة.
- تفاصيل فحص الصحة تظهر في وضع التطوير، وتختصر في الإنتاج لتجنب كشف معلومات داخلية.
- سجلات تطبيق وأمان، ومعرف طلب لربط صفحة الخطأ بسجل الخادم.
- إمكان إعداد تنبيه أخطاء أو تكامل مراقبة اختياري وفق بيئة التشغيل؛ لا يثبت وجود إعداد فعلي لكل خدمة.
- واجهة إدارة Django للأعمال الإدارية المخولة، إلى جانب شاشات التطبيق.

### 19.4 النسخ الاحتياطي

يتضمن المشروع أمرًا لإنشاء نسخة قاعدة بيانات SQLite أو PostgreSQL، مع تحديد مجلد الإخراج وعدد النسخ المحتفظ بها والتحقق من الملف. يدعم اختبار استعادة SQLite إلى ملف مؤقت، وتشفيرًا اختياريًا بمفتاح بيئة عند توفير مكتبة `cryptography`.

```powershell
python manage.py backup_db --verify
```

يوجد أمر منفصل لرفع ملف نسخة إلى تخزين متوافق مع S3، ويتطلب إعداد الخدمة وبياناتها ومكتبة `boto3`. يمكن جدولة الأوامر بأدوات نظام التشغيل؛ ولا يعني وجودها أن النسخ اليومي أو الرفع السحابي مفعلان بالفعل.

النسخ المذكور خاص بقاعدة البيانات. يلزم تضمين الصور والوسائط المرفوعة وبيئة النشر في خطة النسخ المناسبة بصورة منفصلة. كما أن العمليات غير المرفوعة من IndexedDB في جهاز المندوب لا تدخل في نسخة قاعدة الخادم. راجع [دليل النسخ الاحتياطي](../BACKUP.md).

## 20. نطاق الميزات وحدودها ونتائج التحقق

### 20.1 ما يحتاج إعدادًا إضافيًا أو لا يثبته الكود الحالي

| الموضوع | التوصيف الدقيق |
|---|---|
| توحيد العلامة التجارية | الأسماء والعلامة الثابتة والشعار المرفوع غير موحدة في كل المواضع |
| الطباعة المباشرة | تتطلب جسر Electron أو QZ مجهزًا؛ PWA يستخدم المتصفح افتراضيًا |
| العمل دون اتصال | يشمل المسارات المدعومة والمجهزة؛ ليس كل إجراء إداري أو تصدير |
| دقة رصيد جهاز مفصول | آخر لقطة وأثر عملياته، مع تحقق نهائي عند المزامنة |
| تكلفة البيع بالسالب | تقديرية، ولا تعاد كتابة الأرباح القديمة بمجرد وصول بضاعة لاحقًا |
| حد الائتمان | حقل محفوظ، دون ادعاء منع شامل آلي لكل تجاوز |
| الدفع بالمحفظة أو البنك | تسجيل ومتابعة داخلية؛ لا يوجد إثبات لتحويل آلي عبر مزود دفع |
| واتساب | بيانات اتصال وتفاعلات مسجلة، دون إرسال آلي مفترض |
| الضرائب والفاتورة الإلكترونية | وجود رقم ضريبي لا يساوي احتساب ضريبة أو تكاملًا حكوميًا |
| التصنيع والخام | تسجيل شراء خام مالي، دون دورة إنتاج ومكونات وتصنيع متكاملة |
| المحاسبة العامة | كشوف ومديونيات وحركة نقد وربح تشغيلي؛ دون ادعاء دفتر أستاذ وقوائم قانونية كاملة |
| الرواتب والعمولات | تقرير أداء موظفين ومندوبين لا يثبت نظام رواتب أو احتساب عمولة تلقائيًا |
| النسخ والتشفير والسحابة | أوامر متاحة تتطلب إعدادًا وتشغيلًا وجدولة فعلية |

### 20.2 التحقق الموثق سابقًا لهذه النسخة

بحسب [تقرير مراجعة 16 نوفمبر 2026](full-business-audit-2026-11-16-ar.md)، شمل التحقق المنفذ للكود:

- نجاح **544 اختبار Django على PostgreSQL** دون فشل أو تخطٍّ.
- تشغيل **544 اختبارًا على SQLite** دون فشل، مع تخطي ثلاثة اختبارات تتطلب PostgreSQL.
- نجاح **40 اختبار JavaScript**.
- مراجعة فعلية عبر Chromium للبيع والقبض والكشف دون شبكة، وإعادة الفتح والمزامنة ومنع التكرار وتسوية السالب والتنقل لتفاصيل حركة المنتج.
- مراجعة **16 شاشة عند 8 أحجام**، بإجمالي **128 حالة عرض**، مع تفاعل وطباعة.
- نجاح فحوص Django واتساق الترحيلات وصياغة الكود وتوافق الحزم والتحليل الثابت المذكور في التقرير.

هذه نتائج المراجعة السابقة الموثقة، وليست ادعاء بإعادة تشغيل الاختبارات لمجرد إنشاء هذا الملف. إعداد التقرير الحالي لم يتطلب تعديل منطق التطبيق أو قاعدة البيانات.

### 20.3 البيانات التاريخية والنشر

أظهر الفحص السابق لنسخة من قاعدة SQLite المحلية **23 إشارة تحتاج مراجعة**: ثلاث إشارات تخص فاتورة واحدة، و20 موضع مخزون تحتاج مطابقة كمياتها مع الدفعات. قد تكون بعض فروق الدفعات من أرصدة افتتاحية قديمة، ولا تثبت وحدها عجزًا ماديًا. لم تُعدل الأرصدة تلقائيًا لإخفاء الفروق.

الاختبارات لا تثبت أن خادم الإنتاج أو أجهزة المندوبين محدثة. كما تحتاج إعدادات أمان النشر إلى تحقق في بيئتها الفعلية؛ فقد أظهرت مراجعة إعدادات التطوير تحذيرات موثقة في تقرير الحسابات. يعتمد اعتماد النسخة التشغيلية على نشر الكود والترحيلات والملفات وتحديث PWA وتجهيز كل جهاز، مع الحفاظ على طوابير العمليات المحلية.
